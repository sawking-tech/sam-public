# Долгая память: запись и поиск

Факты лежат в MongoDB: люди и их роли, устройство места, договорённости, навыки, наблюдения. Qdrant хранит к ним
оглавление — краткое описание и вопросы, на которые факт отвечает. Поиск находит факт по смыслу и по словам, текст
всегда берёт из Mongo (ADR-009). Когда факты пишутся сами и когда идёт обслуживание —
[compression](../../architecture/context/compression.md).

`gateway/rag.py` (`RAGStore`), слова — `gateway/lexical.py`, Mongo — `gateway/repos/memory_repo.py`, поиск на
входе хода — `gateway/recall.py`.

## Запись

| Действие | Исполнение |
|---|---|
| правда | документ `_memories` в Mongo: полный текст, стабильный `_id`, теги, счётчики доступа, `last_used_at` |
| оглавление | один факт — несколько точек Qdrant (коллекция `context`): summary и каждый вопрос из `questions` (фасеты, приём в духе HyDE); вопросов нет — одна точка по summary |
| дубль | tool `remember` и `POST /sam/memory` сначала зовут `find_duplicate`: фасет факта с косинусом не ниже `DEDUP_SIM_THRESHOLD` (0,92) к summary нового — второй записи нет, ответ «Уже помню» с текстом записи; извлечение фактов перед сжатием отсекает повтор своим порогом `SAM_MEMORY_DUP_SCORE` ([compression](../../architecture/context/compression.md)); запись скиллов сверяет свои записи по имени скилла |
| правка | `update` меняет только Mongo; вектор пересобирается при `reindex=True` |
| удаление | `forget_by_id`, `forget_by_query` удаляют из Mongo и Qdrant |

## Поиск

1. Вектор: запрос, эмбеддинг, Qdrant, кандидатов `top_k` x 3, лучший фасет на факт; порог 0,5
   (`DEFAULT_SCORE_THRESHOLD`) режет только эту ветку. Свой порог для фактов с меткой — `SAM_RAG_TAG_MIN`
   («метка=порог» через запятую, по умолчанию `skill=0.7`: верные совпадения со скиллами 0,8-1,0, ложные до 0,64).
2. Слова: BM25 по тексту, summary и тегам фактов из Mongo (`SAM_RAG_LEXICAL`, по умолчанию включено, читает до
   `SAM_RAG_LEXICAL_SCAN` 5000 фактов): имя одним словом вектор почти не различает.
3. Слияние RRF; запрос из одного слова (`SAM_RAG_SHORT_QUERY_TOKENS`) — сначала найденное по словам.
4. Текст и признак архива — из Mongo по `mongo_id`; архивные факты отбрасываются.
5. MMR (λ 0,7) умеет убрать почти одинаковые факты из выдачи, но поиск хода его не включает: два факта почти одним
   текстом приходят в контекст оба. Тест на это помечен xfail
   (`tests/test_rag.py::test_near_identical_facts_do_not_both_reach_the_turn`).

Пока эмбеддер грузится, поиск идёт одними словами. Эмбеддер — `paraphrase-multilingual-MiniLM-L12-v2` (384)
отдельным процессом `gateway/embedder_service.py` на `SAM_EMBEDDER_URL`; процесс не отвечает — модель грузится в
шлюзе (около 30 с). Нет модели и процесса — `EmbedderUnavailableError`, размерность не совпала с коллекцией —
`DimensionMismatchError`, нулевой вектор вместо ошибки не пишется.

Ход, критик, воркер и tools памяти зовут поиск через `asyncio.to_thread`. На входе хода — голос, чат, inject —
поиск идёт до выбора основной модели со сроком `VOICE_RAG_TIMEOUT_S` (1,5 с); опоздавшие факты модели вне шлюза приходят тиком `rag`
(`recall.py`).

## Обслуживание

| Метод | Работа |
|---|---|
| `expand_facets` | добавить вопросы-фасеты факту |
| `prune_dead_facets` | убрать фасеты без попаданий старше 90 дней |
| `prune_unused` | удалить факты без использования дольше 90 дней |
| `reindex_all` | пересобрать все векторы из Mongo: смена модели эмбеддингов, расхождение Qdrant и Mongo |

Ночная консолидация (`gateway/dream.py`, [compression](../../architecture/context/compression.md)) зовёт
`prune_dead_facets` при `SAM_DREAM_APPLY=1`; у остальных методов вызывающего в коде нет, их зовут из Python руками.
`expand_facets` и `prune_unused` задуманы шагами консолидации, но факты в Mongo консолидация меняет только после
живой проверки ночного запуска. `reindex_all` — ручной инструмент ADR-009 на смену эмбеддера и расхождение индекса,
расписания ему не нужно.

## «Запомни» и возврат к прошлому

Просьба «запомни» раскладывается на две части: содержание — фактом в долгую память (`remember`), он живёт
независимо от окна и находится поиском; намерение («напомнить про доктора», «вернёмся к утренней теме») — в канал
мыслей ([compression](../../architecture/context/compression.md), раздел «Два канала»), который сжимается отдельно и
не вытесняется новыми беседами (ADR-027). Напоминание к сроку основная модель ставит себе кроном или workflow: в
тишине она просыпается только от входящих.

Подробности сжатой беседы основная модель поднимает из архива (`sessions_archive`) инструментом `recall_history` по
теме; поиск по памяти архив не охватывает. Поднятое не копируется в историю: в MongoDB пишется одна запись-ссылка
«вернулись к прошлому разговору» с отрезками архива, журнал остаётся линейным. При сборке контекста шлюз вставляет
отрезки в окно по времени, между несмежными кусками — маркеры пропуска, окно расширяется на `SAM_RECALL_WINDOW`
(20) сообщений. Дальше сжатие идёт по обычным правилам, расширение сходит на нет само.

## Не закрыто

- MMR в поиске хода не включён: почти одинаковые факты приходят оба (см. «Поиск», п. 5).
- Qdrant догоняет Mongo только при `reindex_all`; Change Streams не используются.
- `expand_facets` и `prune_unused` без вызывающих до живой проверки консолидации; перед подключением `prune_unused`
  нужен выбор автора: архив, как задумано, или удаление, как в коде.

## Настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SAM_EMBEDDER_URL` | `http://127.0.0.1:10204` | процесс эмбеддера; не отвечает — модель грузится в шлюзе |
| `SAM_RAG_LEXICAL`, `SAM_RAG_LEXICAL_SCAN` | 1, 5000 | словесная ветка и сколько фактов читает |
| `SAM_RAG_TAG_MIN` | `skill=0.7` | пороги векторной ветки для фактов с меткой |
| `SAM_RAG_BM25_K1`, `SAM_RAG_BM25_B`, `SAM_RAG_RRF_K` | 1,2, 0,75, 60 | параметры BM25 и слияния RRF |
| `SAM_RECALL_WINDOW`, `SAM_RECALL_GAP_S` | 20, 300 | окно `recall_history` и пометка пропуска между кусками |
| `SAM_DREAM`, `SAM_DREAM_APPLY` | 0, 0 | ночная консолидация и удаление мёртвых фасетов |
