# Живые приложения

Страница или сервис, который SAM сделала и который продолжает работать: график, доска тренажёра, мини-приложение.
Песочница (`sandbox_run`) исполняет код один раз; приложение живёт, отвечает странице и переживает перезапуск
стенда. Почему контейнер — ADR-016, почему отдельное приложение — ADR-021.

`gateway/apps.py` (манифест, команды docker, жизненный цикл), `gateway/apps_edge.py` (пересыльщик),
`gateway/main.py` (маршрут `/apps/<slug>/...`, подъём при старте).

## Состав приложения

- Папка `data/apps/<id>/` (`SAM_APPS_DIR`): манифест `app.json` — имя, описание, команда запуска, порт внутри
 (8000 по умолчанию), порт на хосте, когда, кем и по какой просьбе сделано, `wanted` (`running` или `stopped`); код
 — в `src/`. В контейнер монтируется только `src/`: из манифеста шлюз берёт порт, и приложение его не перепишет.
 Манифест с чужим id или портом вне диапазона не читается.
- Адрес — `slug` в манифесте: латиница, цифры и дефис из имени, кириллица транслитом (`anyascii`), основа
 не длиннее 40 знаков, имя без букв и цифр даёт `app`. Занятый slug или id получает суффикс `-2`, `-3`; `monitor` и
 `radar` (`RESERVED_SLUGS`) приложению не выдаются. Slug не меняется: папка, контейнеры и сети по-прежнему по id.
 Старому манифесту без slug он выдаётся при первом чтении (`apps.scan`) и записывается в файл, старшему по
 `created` — без суффикса.
- Контейнер приложения `sam-app-<id>`: образ песочницы `sam-sandbox:2`, папка приложения в `/work`, те же
 ограничения, что у песочницы (`sandbox.hardening`: лимиты `SAM_SANDBOX_*`, корень только для чтения, uid 1000,
 без capabilities, только локальный образ, без переменных шлюза). Сеть — своя `sam-app-net-<id>` с `--internal` и
 подсетью /28 из `SAM_APPS_SUBNET_BASE` (10.231.0.0/16) по номеру порта: пул Docker по умолчанию кончается на ~30
 сетях.
- Пограничный контейнер `sam-app-edge-<id>`: `apps_edge.py`, смонтированный только для чтения, пересылает TCP к
 приложению. Стоит во внутренней сети приложения и в общей сети пограничных `sam-apps-edge`, порт
 опубликован только на `127.0.0.1` хоста, из диапазона `SAM_APPS_PORT_BASE` (18400) на `SAM_APPS_PORT_SPAN` (200).
 Сменить диапазон после того, как приложения созданы, нельзя: их манифесты с портом вне нового диапазона не
 читаются, приложения пропадают из прокси, `revive` пишет ошибку на каждое.

## Встроенные приложения: монитор и радар

Встроенное приложение — процесс вне контейнерного рантайма (`gateway/builtin_apps.py`): монитор — страница шлюза
`/monitor`, радар — сервис `radar.presence_service` (:8010, `start_radar.ps1`). Манифест `data/apps/<slug>/app.json`
со slug `monitor` или `radar` и видом `builtin`: имя, описание, адрес (`url`), health check (`/health` шлюза,
`/health` радара — проверка та же, что у надзора, `gateway/stand_checks.py`), имя компонента `restart_component`
(`control`). Манифест поставляет SAM: шлюз при старте и панель при сборке пишут его, если файла нет или он разошёлся
с поставляемым (адреса из `SAM_SERVER` и `SAM_RADAR_URL`). Папка не из 12 hex контейнерным приложением не читается.

Функции радара — маршруты его FastAPI с меткой `openapi_extra={"x-sam-tool": True}` (`radar/presence_sam_api.py`):
ручки `where`, `history`, `layout`, `tell`, `devices`, `furniture`, имя из operationId. `app_list` читает OpenAPI с
адреса радара (`Builtin.url`) с ключом доступа, как прокси шлюза (`builtin_proxy.auth_headers`); радар не
отвечает — строка «не отвечает». `app_call(radar, where, {person})` вызывает ручку там же: GET — аргументы строкой
запроса, POST — JSON-телом. В манифесте функций нет. Модели без `app_call` (Cortex, сессия только с MCP стенда)
получают те же ручки инструментами `radar_*` переходника `mcp/radar_server.py`.

- `/apps/monitor/` и `/apps/radar/` шлюза отвечают 307 на настоящий адрес; 127.0.0.1 и localhost в нём заменяются
 хостом запроса. Прокси не годится: страница радара ходит в свой API путями от корня (`/sam/presence/...`) и под
 `/apps/radar/` их бы потеряла, а CSP sandbox прокси закрыл бы ей скрипты с origin. 307, а не 308: после выноса
 радара в свой контейнер адрес может стать `/apps/radar/` шлюза.
- `app_list` показывает встроенные первыми. `app_update` и `app_stop` их не трогают: ответ называет
 `restart_component radar` или говорит, что монитор — часть шлюза.
- Монитор не удаляется ни кнопкой, ни API панели и закреплён всегда. Радар — опция: удаление с подтверждением
 slug останавливает сервис, снимает манифест и кладёт в `data/apps/radar/` метку `removed`; `ensure` его больше не
 ставит, агрегатор MCP после перезапуска (`restart_component mcp`) не поднимает сервер `radar`, и функций
 `radar_*` нет. Данные `data/presence_*` остаются. Вернуть — `POST /api/apps/radar/install`.
- Запуск радара — `restart_component radar` (`restart.plan`, `SAM_RESTART_CMD_RADAR`, на Windows `start_radar.ps1`),
 остановка — `SAM_APPS_STOP_CMD_RADAR`, на Windows `start_radar.ps1 -Stop`; вывод — `logs/builtin-apps.log`.
 Монитор отдельно не запускается и не останавливается.

## Закрепление, настройки, каркас

Поля манифеста, которые SAM задаёт в `app_make` и `app_update` без кода и без перезапуска
(`gateway/tools/apps.py`, `_extras`):

- `pinned` — плитка в верхнем ряду рядом с монитором и радаром и ссылка в полосе каркаса на всех страницах SAM.
 Ставит SAM по просьбе (`app_update` с `pinned`) или человек в панели.
- `settings` — поля `{name, type: text|number|bool|choice, default, label, options}`
 (`gateway/app_settings.py`, до 20 полей). Значения — в `data/apps/<id>/settings.json`, вне `src/`. Страница читает
 их адресом `sam-settings.json`: шлюз отдаёт его из файла, а не из контейнера, поэтому их видит и страница без
 сервера. Сохранение в панели проверяет типы и перезапускает приложение.
- `shell` — каркас вокруг страницы ([shell.md](shell.md)): по умолчанию весь; `{off: true}` — своя
 полноэкранная страница; `{bar: false, panelw: 360}` — свои опции.
- `tools` — ручки приложения для SAM: `{name, description, method, path, params}`, вызов — `app_call`.
- `icon` — лого плитки разметкой SVG, разбор в разделе «Лого плитки».

## Из задачи песочницы

У приложения нет сети, поэтому пакеты собираются в песочнице: `sandbox_run` с `packages` и файлами, проверка там же,
затем `app_make` (или `app_update`) с `from_job` — job задачи и, если нужно, `from_path` — её подпапка. Шлюз
копирует дерево задачи в `src/` байтами под замком задачи, без ссылок, спецфайлов и `.git`; `.pkgs` и
`node_modules` переносятся, `PYTHONPATH=/work/.pkgs` задан в образе; при `from_path` пакеты из корня задачи кладутся
в корень приложения. Исполняемые файлы остаются исполняемыми (0755, без setuid); ссылки `node_modules/.bin` не
переносятся — программы пакетов запускаются через `python -m модуль` или `node путь/к/cli.js`. `files` ложатся
поверх копии. `app_update` с `from_job` собирает `src/` заново в соседней `src.new`: сбой сборки не трогает
работающее приложение, обмен идёт при остановленных контейнерах, не запустилось — прежний `src/` возвращается и
поднимается. Потолки — `SAM_APPS_EXPORT_MAX_FILES` (20 000) и `SAM_APPS_EXPORT_MAX_BYTES` (300 МБ); при отказе
папки приложения не остаётся. В журнал задачи пишется строка `export`: приложение, файлы, байты, пропущенное
(`gateway/sandbox.py`, `export_job`).

## Изоляция

| Откуда | Куда | Итог |
|---|---|---|
| приложение | интернет | закрыто: внутренняя сеть без выхода |
| приложение | хост, шлюз, MCP | закрыто |
| приложение | соседнее приложение | закрыто: у каждого своя внутренняя сеть |
| приложение | окружение и данные шлюза | нет: смонтированы только свой код (`/work`) и свои данные (`/data`) |
| страница в мониторе | API шлюза, cookie | закрыто: ответ идёт с `Content-Security-Policy: sandbox allow-scripts` |
| другие устройства сети | порт приложения | закрыто: порт только на 127.0.0.1 |
| другие устройства сети | `/apps/<slug>/` шлюза | как весь шлюз (`gateway/access.py`): без `SAM_API_KEY` только с этой машины, с ключом — по ключу |
| процессы этой машины | порт приложения | открыто: порт на 127.0.0.1 доступен локально мимо CSP шлюза |

## Жизненный цикл

- **Создать** — `apps.create`: папка, файлы, манифест, свободный порт, запуск.
- **Запустить** — `apps.start`: старые контейнеры убираются, сети заводятся, приложение и пограничный стартуют;
 ошибка — одной строкой, ничего не остаётся запущенным.
- **Остановить** — `apps.stop`: контейнеры и сети удаляются, `wanted=stopped`, папка остаётся.
- **Данные** — `data/apps/<id>/data`, в контейнере `/data`: создаётся при запуске, обмен кода и пересоздание
 контейнера её не трогают, уходит с удалением приложения. Одно действие над приложением за раз — замок
 `apps.app_lock`.
- **Перезапуск стенда** — контейнеры с `--restart unless-stopped` переживают перезапуск Docker и ПК; при старте
 шлюза `apps.revive` поднимает приложения с `wanted=running`, которые не работают.
- **Показ** — `GET /apps/<slug>/...`: запрос на `127.0.0.1:<порт>`, ответ с CSP sandbox. Остановлено — 404; не
 отвечает — 502 одной строкой. Браузеру (GET и `text/html` в Accept) вместо ошибок — заглушка 503 на все
 приложения: «приостановлено» или «не отвечает» и где продолжить (`gateway/app_stub.py`). Потолки: ответ за 30 с
 и не больше `SAM_APPS_PROXY_MAX_BYTES` (20 МБ), тело не больше `SAM_APPS_PROXY_MAX_BODY` (2 МБ). Редирект
 остаётся внутри приложения: путь от корня переписывается в `/apps/<slug>/...`, на чужой хост — отбрасывается.
- **Старый адрес** — `/apps/<id>/...` отвечает 308 на `/apps/<slug>/...` с тем же путём и запросом; 308 сохраняет
 метод и тело POST.

## Инструменты SAM

Воркер пишет код приложения сам, как для `sandbox_run` (`gateway/tools/apps.py`, регистрация в `gateway/agent.py`):

| Инструмент | Что делает |
|---|---|
| `app_make(name, files, command, request)` | всегда новое приложение, ответ — slug и адрес `SAM_SERVER/apps/<slug>`; сервер на порту 8000 в папке; в монитор — событие `app_result` |
| `app_update(app, files, command, pinned, settings, shell)` | правка: файлы целиком, команда — если меняется; приложение перезапускается; только `pinned`, `settings`, `shell` — без перезапуска |
| `app_list` | slug, имя, работает ли, адрес страницы, id; битые манифесты — строками |
| `app_call(app, tool, args)` | вызов ручки приложения из `app_list` без браузера |
| `app_stop(app)` | остановить; папка и код остаются |

`app` — slug или id. По имени приложение не ищется: имя без slug получает отказ со списком slug приложений с этим
именем. `app_make` с именем существующего приложения делает новое со slug `<имя>-2` и старое не трогает. Правит
только `app_update` с явным slug или id.

## Страница приложений

Страница `/apps` (`gateway/apps_api.py`, `gateway/static/apps_panel.html`) — встроенное приложение шлюза, как монитор:
манифест поставляет шлюз (`gateway/builtin_apps.py`), health check — `/health` шлюза, удалить нельзя, прежний адрес
`/apps-panel` ведёт на `/apps`. Docker страница не трогает: она зовёт API стенда на шлюзе, контейнерами управляет
ядро (`gateway/apps.py`), встроенными — их команды.

Плитка — лого приложения, если SAM его нарисовала (поле `icon`), иначе живая миниатюра страницы (фрейм с CSP
sandbox, уменьшенный; у встроенных — знак), имя и состояние точкой: работает, приостановлено, не отвечает. Нажатие
открывает приложение, на углу — «приостановить» или «продолжить» (у приложений и монитора нет) и шестерёнка.
Закреплённые — верхним рядом: встроенные всегда, свои — по `pinned`. Список — файлы с диска, шлюз кладёт его в
страницу, плитки видны в первом кадре. «Не отвечает» плитка узнаёт сама: браузер пингует её страницу (`fetch` к
адресу встроенного или к порту приложения). Обновление раз в 10 с меняет только изменившиеся плитки. Своих
приложений нет — подсказка, как попросить SAM.

Шестерёнка открывает панель: описание, просьба человека его словами, когда сделано, адрес и slug, функции (у
радара), «Закрепить» или «Открепить», «Приостановить» или «Продолжить», настройки, если объявлены, и внизу
приглушённо «Удалить»: кнопка активна, только когда введён slug. Снятый радар — плитка «Поставить радар».

API стенда: список — `GET /sam/apps`, настройки — `GET /sam/apps/{slug}/settings`, действия —
`POST /sam/apps/{slug или id}/{start|stop|pin|unpin|settings|delete|install}`. Docker в действиях идёт в потоке.
Защита — доступ шлюза (`gateway/access.py`): ключ `SAM_API_KEY` или эта машина; без ключа Host только этой машины
(DNS rebinding — 403); POST только с `Content-Type: application/json` (простой POST чужой страницы — 415); действие
с Origin чужой страницы — 400.

### Лого плитки

Поле `icon` — разметка SVG строкой, до `apps.ICON_MAX_CHARS` (20 000) знаков, начинается с `<svg`; пустая строка
снимает лого. Задаётся параметром `icon` у `app_make` и `app_update`, смена лого приложение не перезапускает.
Плитка показывает его картинкой (`<img>` с data URI): скрипты внутри SVG в картинке не исполняются. У встроенных
поле есть; пусто — знак из страницы. Миниатюра скриншотом не сделана.
