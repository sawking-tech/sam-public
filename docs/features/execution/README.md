# execution

Где выполняется код и живут страницы. Три разных вещи, и различаются они временем жизни: песочница исполняет код один
раз, приложение живёт и отвечает странице, каркас задаёт вид всем страницам стенда.

| Файл | Механизм |
|---|---|
| [sandbox.md](sandbox.md) | код в контейнере: без секретов и данных стенда, сеть `none` по умолчанию и по запросу под файрволом, установка пакетов с проверкой OSV, файлы внутрь и наружу только копией шлюза, лимиты `SAM_SANDBOX_*`, тёплая песочница для быстрых кусков |
| [apps.md](apps.md) | живые приложения: папка `data/apps/<id>` с манифестом, контейнер `sam-app-<id>` с теми же ограничениями, своя сеть /28 и пограничный контейнер, slug из имени с транслитом, маршрут `/apps/<slug>/`, жизненный цикл и закрепление |
| [shell.md](shell.md) | общий каркас страниц: полоса с навигацией, колонка до 1120 px, выдвижная панель 272 px; `shell.css`, `panel.js`, `boot.js` — копии из `DotNetSolutionKit/site`, своё у SAM — токены и API панелей |

Почему контейнер и почему отдельное приложение — [ADR-016](../../adr/016-sandbox-container-per-run.md) и
[ADR-021](../../adr/021-internal-services-isolated-web-apps.md).
