# Прогон и трасса хода

Проверка разговора без живых людей и этапы, из которых сложился ход.

`gateway/evals.py`, `scripts/eval_voice.py`, `gateway/token_usage.py` (`trace_turn`).

## Прогон на наборе случаев

Случай — фраза и ожидание, которое проверяет код: вызван ли `spawn_agent`, ответ или молчание, нет ли обещания
действия без вызова. Набор из истории собирается командой, прогон идёт без записи в историю:

```bash
python scripts/eval_voice.py export   # data/evals/cases.jsonl, вне git
python scripts/eval_voice.py run      # итог JSON, ходы в историю не пишутся
```

`export` берёт до `--limit` (200) последних случаев из каждой сессии истории Mongo. Без своего набора `run` берёт
образец `tests/fixtures/voice_eval_cases.py`; свой файл задаётся `--cases`. Нужны Mongo и поставщик LLM, как у
gateway; токены и этапы хода пишутся в `_token_usage`, как у живого хода. Итог: сколько случаев, сколько прошло,
провалы с причиной, медиана и максимум задержки.

## Трасса хода

Внутри `token_usage.trace_turn` этапы хода пишутся в поле `stages` записи `_token_usage`, миллисекунды от начала
хода:

| Этап | Момент | Источник этапа |
|---|---|---|
| `history` | история сессии прочитана | голосовой ход |
| `rag` | память к фразе найдена | голосовой ход |
| `route` | модель под ход выбрана | голосовой ход |
| `context` | контекст собран | голосовой ход |
| `first_token` | первая дельта ответа | любой стримовый вызов (`gateway/llm_client.py`) |

Этапы ставятся один раз за ход: повторный `mark_stage` того же имени значение не меняет. Вне `trace_turn` разметка
ничего не делает, и запись идёт без `stages`. Трассу сейчас ведёт голосовой ход (`gateway/voice_turn.py`); обычный
ход шлюза пишет только `first_token`, если ответ шёл стримом.

Этапы голосового слоя — первое предложение на синтез, первый звук — шлюз не видит: они в логе слоя (строка «до
звука» в `voice/layer/say_out.py`).
