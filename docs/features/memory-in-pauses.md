# Работа с памятью в паузах

Сжатие истории, извлечение фактов и ночная консолидация идут только в паузах разговора. Почему не по счётчику
сообщений и не в ходе - ADR о памяти в паузах.

| Что | Как | Задача |
|---|---|---|
| ворота простоя | работа начинается, когда `SAM_IDLE_S` (30) секунд нет хода, текстового или голосового (`gateway/idle_gate.py`); сжатие ждёт паузы не дольше `SAM_COMPRESS_IDLE_MAX_S` (300 с), потом идёт без неё | SAM-62, SAM-97 |
| порог сжатия | токены несжатой истории: окно `SAM_COMPRESS_KEEP_TOKENS` (600), кусок за окном `SAM_COMPRESS_CHUNK_TOKENS` (250); счёт по символам (`SAM_CHARS_PER_TOKEN`, 3,3): `usage` поставщика приходит на вызов, а не на сообщение; потолок `SAM_COMPRESS_CEILING` (28 сообщений) или `SAM_COMPRESS_CEILING_TOKENS` (2100) сжимает и без паузы | SAM-62, SAM-97 |
| извлечение фактов | перед удалением куска истории LLM извлекает факты; только добавление, с источником (сессия и отрезок времени), повтор отсекается по сходству `SAM_MEMORY_DUP_SCORE` (0,85); включается `SAM_MEMORY_AUTOWRITE=1` | SAM-63 |
| консолидация | ночью по расписанию внутри тех же ворот (`gateway/dream.py`, `SAM_DREAM=1`, окно `SAM_DREAM_FROM_H`-`SAM_DREAM_TO_H`, 3-6 ч, раз в `SAM_DREAM_INTERVAL_H`, 20 ч): отчёт о фактах и векторах, удаление из Qdrant векторов без попаданий за 90 дней (только при `SAM_DREAM_APPLY=1`); слияние повторов и забывание - следующий шаг | SAM-22 |
| состояние | идущее сжатие - флаг сессии в памяти процесса; несжатое считается по `sessions` в Mongo, сводная сводка - `meta_repo` | SAM-62 |
