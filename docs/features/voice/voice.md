# Голос: вход

Микрофон, эхоподавление, распознавание и опознание говорящего. Всё работает одним процессом
`voice/layer/voice.py`: эхоподавлению нужны рядом сигнал колонок и сигнал микрофона (ADR-011, ADR-017).

## Звук

`AudioCore` держит микрофон и колонки 48 кГц моно и вычитает речь SAM из микрофона эхоподавлением WebRTC APM,
поэтому человек слышен поверх речи. Почему так - ADR-011 и ADR-017.

### Один процесс

`python -m voice.layer.voice [папка-шины] [--device N] [--no-aec]` (`voice/layer/voice.py`) запускает ядро
`AudioCore` (`voice/layer/audio_core.py`), слух (раздел «Слух» ниже) и озвучку ([speech.md](features/voice/speech.md)) вместе: два процесса со
своими потоками дрались за звук, а эхоподавлению нужны в одном месте и сигнал колонок, и сигнал микрофона. Модели
Whisper грузятся до открытия звука, чтобы за 20 с загрузки не копилась очередь блоков.

| Что | Значение | Где |
|---|---|---|
| частота колонок и микрофона | 48 кГц, моно, int16 | `RATE` |
| кадр эхоподавления | 10 мс (480 сэмплов): другой длины APM не принимает | `FRAME` |
| блок потока | 40 мс (1920 сэмплов): на MME блок 10 мс не успевает и звук рвётся | `BLOCK` |
| микрофон слуху | после AEC ФНЧ 7,6 кГц и каждый третий сэмпл - 16 кГц блоками по 100 мс | `OUT_RATE`, `OUT_BLOCK` |
| подписчики узла | копия каждого чистого блока - виртуальным входам по TCP `:10210` (`SAM_VOICE_HUB_PORT`, `voice/layer/vmic.py`) | `AudioCore.mic_tap` |

### Эхоподавление

WebRTC APM из livekit (`rtc.AudioProcessingModule`): эхоподавление и фильтр низких частот включены, шумоподавление
выключено - при двойной речи оно срезало голос человека. Каждый кадр колонок идёт в APM эталоном
(`process_reverse_stream`), каждый кадр микрофона проходит `process_stream`. Нет livekit - ядро работает без
эхоподавления и пишет об этом одну строку; `--no-aec` выключает его явно.

APM нужна задержка между кадром в колонки и его эхом в микрофоне. Заявленная устройствами задержка на мониторах по
HDMI и DP меньше настоящей (в замере эхо до 3000 RMS вместо 35-200), поэтому она меряется:

| Шаг | Как |
|---|---|
| сигнал | свип 300-5000 Гц, 0,5 с, амплитуда 3000 (около -21 дБ), края сглажены (`cal_signal`) |
| замер | запись сырого микрофона до AEC, сдвиг по взаимной корреляции в пределах 0-1 с (`find_lag`); слуху на это время отдаётся тишина |
| доверие | корреляция от 0,2 (`CAL_MIN_CORR`) и сдвиг 20-600 мс (`CAL_MIN_MS`, `CAL_MAX_MS`); иначе берётся заявленная задержка потоков |
| кэш | по имени выхода в `SAM_SPEAKER_CALIBRATION` (по умолчанию `data/voice/voices/speaker-calibration.json`); выход из кэша калибровку не повторяет |
| перекалибровка | файл `calibrate` в папке шины: в ближайшую тишину ядро калибрует текущий выход, перезаписывает кэш и удаляет файл |

### Смена выхода

Раз в 2 с (`DEVICE_POLL`), когда никто не говорит (очередь колонок пуста, нет флагов `speaking` и `hearing`), ядро
спрашивает у winmm системный выход по умолчанию: список PortAudio застывает на момент запуска. Выход сменился -
колонки переоткрываются на нём, задержка берётся из кэша или калибровкой. Нового устройства нет в списке PortAudio -
PortAudio перечитывается целиком, микрофон при этом переоткрывается. Устройство не нашлось или не открылось - ядро
остаётся на прежнем выходе и это имя больше не пробует. Не на Windows системный выход не отслеживается.

### Сторож микрофона

Колбэк PortAudio при пропаже устройства просто перестаёт приходить, без ошибки (так отвалилась USB-камера с микрофоном),
поэтому потеря распознаётся по времени с последнего блока (`voice/layer/mic_watch.py`).

| Что | Значение |
|---|---|
| вход замолчал | блоков нет дольше `VOICE_MIC_STALL_SECS` (2 с): строка в лог, событие `lost` в `mic.jsonl`, тикер шлёт ведущему `mic`; слух бросает недослушанную фразу и снимает флаг `hearing` |
| ожидание | раз в `VOICE_MIC_POLL_SECS` (2 с) ядро ищет то же устройство в списке входов winmm; нашлось - PortAudio перечитывается, вход и колонки переоткрываются в том же процессе, задержка AEC выставляется заново; посреди речи SAM не перечитывает |
| вернулся | первый блок после потери - событие `back` |
| старт без микрофона | строка `[слух] нет микрофона; жду устройство` и событие `missing`; колонки работают |
| имя устройства | сравнивается по началу: winmm и MME режут имя до 31 знака |

Выбор входа: `--device`, иначе `MIC_DEVICE` (индекс или часть имени), иначе системный (`hearing.pick_device`).

### Громкость речи

Громкость колонок меняется плавно по блокам, без щелчков: `duck(level)` - шагом 0,15 за блок 40 мс (около 0,3 с на
притихание), `fade_out(seconds)` - до нуля и очистка очереди, `wind_down` - договаривание после перебивания
([speech.md](features/voice/speech.md), раздел «Перебивание»).

### Отладка

- `SAM_VOICE_DEBUG_AEC=1` - раз в секунду, пока SAM говорит, пик микрофона до и после AEC.
- Обрывы колонок и переполнения микрофона - строка в лог, когда счётчик изменился.
- `SAM_VOICE_RECORD_OUT=1` или файл `record-out` в папке шины - звук колонок за время реплик в `speaker.wav`
  (`voice/layer/recorder.py`); тишина между репликами не пишется.

## Слух

SAM слушает всегда, без слова-пробуждения: фраза по паузе распознаётся Whisper и строкой уходит в
`voice-in.jsonl` шины. Почему так - ADR-011. Звук приходит из ядра уже без речи SAM (раздел «Звук» выше); кому сказана
фраза, решает шлюз ([addressee](features/voice/addressee.md)).

`voice/layer/hearing.py`, класс `Listener`, запуск в процессе `voice.layer.voice`.

### Фраза

| Что | Значение | Где |
|---|---|---|
| начало фразы | блок 100 мс громче `VOICE_SILENCE_RMS` (230 RMS int16; фон комнаты в замере около 160); к фразе приклеивается 0,5 с звука до неё | `SILENCE_RMS`, `PREROLL_SECS` |
| конец фразы | тишина `VOICE_SILENCE_SECS` (1,5 с); после 10 с речи - 2,5 с | `SILENCE_SHORT`, `SILENCE_LONG`, `LONG_PHRASE` |
| слишком короткая | меньше 0,5 с звука без тишины в конце - не распознаётся | `MIN_PHRASE_SECS` |
| слишком длинная | 120 с - фраза закрывается | `MAX_PHRASE_SECS` |
| куски по ходу речи | на внутренней паузе от 0,5 с кусок длиннее 2 с уходит в Whisper сразу, его текст пишется строкой с `partial: true`; к концу фразы распознаётся только хвост | `CUT_QUIET`, `CUT_MIN`, `_send_part` |
| флаг `hearing` | лежит, пока идёт фраза: озвучка ждёт её конца ([speech.md](features/voice/speech.md), раздел «Синтез и очередь реплик») | `_start_phrase`, `_finish` |

Пока лежит флаг `mute`, звук отбрасывается, начатая фраза бросается. Пока лежит `speaking` (SAM говорит), слух ловит
только перебивание ([speech.md](features/voice/speech.md), раздел «Перебивание»); фраза, начатая перебиванием, пишется дальше целиком, её начало берётся из
кольца последних 60 с звука.

Конец фразы моделью (Smart Turn v3, `voice/layer/turn_end.py`) в слух не встроен: на 1559 записанных фразах модель
почти не отличала конец фразы от внутренней паузы (AUC 0,60). Адаптивный конец - SAM-66.

### Распознавание

| Что | Значение |
|---|---|
| модель | `WHISPER_MODEL`, по умолчанию `bzikst/faster-whisper-large-v3-russian`, CUDA float16 |
| подготовка звука | шумоподавление `noisereduce` и выравнивание громкости к 3000 RMS (`prepare_audio`) |
| параметры | `language=ru`, `beam_size=1` (beam 5 на 37 с звука - 6,0-6,7 с против 4,8-5,1 с, текст тот же), VAD с тишиной 300 мс, без опоры на прошлый текст, температура 0 |
| словарь терминов | `SAM_VOICE_TERMS` (по умолчанию `voice/layer/terms.txt`) - в `initial_prompt` |
| отсев сегментов | сегмент с `compression_ratio` выше 2,4, `avg_logprob` ниже -1,0 или `no_speech_prob` выше 0,6 выбрасывается |
| галлюцинации | фразы субтитров («Продолжение следует...», «Спасибо за просмотр» и подобные) вырезаются, повтор слова подряд схлопывается, обрывок «и т.д.» как вся фраза отбрасывается (`strip_hallucinations`) |
| секреты | произнесённые ключи команд (`SAM_<НАЗНАЧЕНИЕ>_SECRET` в `.env`) маскируются до записи в шину, число сверяется по цифрам (`gateway/secret_mask.py`, SAM-88, SAM-104); строка получает поле `secret` с именами названных ключей |

Распознавание идёт в одном потоке; кто говорит, считается параллельно (раздел «Опознание голоса» ниже).

### Эхо по тексту

Остаток речи SAM в микрофоне ловится и по тексту: фраза сравнивается с репликами из `say-out.jsonl` за последние
60 с (`ECHO_WINDOW`; реплика могла ждать в очереди). Доля символов фразы, совпавших с репликой кусками от 4 знаков
в том же порядке (`coverage`): у эха 0,96-1,0, у фразы человека на ту же тему 0,20-0,29. Фраза от двух слов с долей
от 0,6 (`ECHO_COVERAGE`) - эхо.

Решение о строке:

1. Голос опознан как свой (`claude`) - эхо.
2. Голос опознан как человек - не эхо, даже если человек повторил реплику SAM слово в слово.
3. Голос не опознан - из фразы выбрасываются предложения, похожие на реплики SAM (после перебивания фраза
   начинается с хвоста речи SAM из кольца); не осталось ничего - эхо.

Мост и тикер строки с `echo: true` и `partial: true` дальше не передают (`voice/layer/bridge.py`,
`voice/layer/ticker.py`).

### Строка `voice-in.jsonl`

`text`, `secs` (длина), `rms` (90-й процентиль громкости), `echo`, `who` и `score` (раздел «Опознание голоса» ниже), `wait` (тишина
в конце), `stt` (сколько ждали распознавания после конца фразы), `wav` (`phrases/ЧЧММСС.wav`); `raw` - исходный текст,
если из него вырезано эхо; `secret` - имена замаскированных ключей. Строка куска по ходу речи - `text`,
`partial: true`, `who`, `score`.

### Записи

В папке шины: `mic.wav` - весь звук за запуск (при перезапуске - `mic-ЧЧММСС.wav`), `phrases/*.wav` - каждая фраза,
`last-phrase.wav` - последняя. Уборка (`voice/layer/retention.py`, SAM-106) раз в `SAM_MIC_SWEEP_EVERY_S` (3600 с)
удаляет `mic*.wav` и `phrases/*.wav` старше `SAM_MIC_KEEP_HOURS` (24 ч), затем самые старые, пока всё не уложится в
`SAM_MIC_KEEP_MB` (600 МБ); самый новый файл и файл, в который слух пишет сейчас, не удаляются.

### Запуск отдельно

`python -m voice.layer.hearing [папка-шины] [--device N] [--no-aec]`; `--list-devices` - список устройств;
`--file phrase.wav` - распознать файл и выйти.

## Опознание голоса

Каждая фраза и каждый кусок фразы получают имя профиля, чей голос ближе, и оценку близости. Имя доходит до шлюза
полем `who` и решает, кому сказана фраза ([addressee](features/voice/addressee.md)), кто может перебить SAM громкостью ([speech.md](features/voice/speech.md), раздел «Перебивание») и что
считать эхом (раздел «Слух» ниже). Почему так - ADR-011. Опознание голоса - не аутентификация: привилегированные
команды требуют ключа (`gateway/secret_mask.py`).

`voice/layer/speakers.py` (SAM-30).

### Как

| Что | Значение |
|---|---|
| модель | ECAPA `speechbrain/spkrec-ecapa-voxceleb` на CPU; кэш модели - `SAM_VOICES_DIR/.model` |
| профиль | средний нормированный эмбеддинг записей человека, `SAM_VOICES_DIR/<имя>.npy` (по умолчанию `data/voice/voices`, вне git) |
| оценка | косинусная близость эмбеддинга фразы к каждому профилю; берётся лучший |
| порог | `VOICE_MIN_SCORE` 0,4: ниже - «неизвестно» (`who: null`), оценка всё равно пишется |
| короткий звук | меньше 0,5 с - не опознаётся |
| свой голос | профиль `SAM_SELF_PROFILE` (по умолчанию `claude`): фраза этим голосом - эхо озвучки SAM, кусок с ним в шину не пишется |
| битый профиль | недописанный файл, не вектор или профиль другой модели эмбеддингов пропускается, о нём одна строка за запуск; остальные опознаются |

Порог 0,4: на 1392 записанных фразах (`python -m voice.layer.speaker_eval score|report`) на 0,4 «неизвестно» 276 фраз,
из них длиннее 6 с - 21, чужой профиль побеждает в 2; на 0,35 «неизвестно» 207, чужой - 5.

Опознание идёт в отдельном потоке параллельно распознаванию. Нет speechbrain или профилей - слух работает без
поля `who` и пишет об этом одну строку; громкостью тогда перебивает любой звук громче порога.

### Профили

```
python -m voice.layer.speakers enroll <имя> <файл.wav> [...]   профиль из записей
python -m voice.layer.speakers enroll-claude                   свой профиль из пяти фраз синтеза голосом по умолчанию
python -m voice.layer.speakers who <файл.wav>                  кто на записи
python -m voice.layer.speakers list
```

Профиль своего голоса снимается заново после смены голоса синтеза.

## Не закрыто

- Калибровка (`find_lag`, доверие к замеру) тестов не имеет; на всех выходах вживую не обкатана.
- Громкость прочего звука из колонок (музыка, видео) в шине не видна: `duck` меняет громкость только речи SAM
  (ADR-017).
- Гость без профиля не опознаётся: громкостью он перебивает SAM, только если звук громче `VOICE_BARGE_RMS_SURE`.
- В одной фразе могут говорить двое: у фразы одно имя; куски по ходу речи опознаются каждый своим голосом.
- Крик опознаётся хуже речи: на крике за 1 с оценка 0,11-0,28.
