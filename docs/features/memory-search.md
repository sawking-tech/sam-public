# Долгая память: запись и поиск

Факты о доме, людях и договорённостях лежат в MongoDB, Qdrant хранит к ним оглавление: краткое описание и вопросы,
на которые факт отвечает. Поиск находит факт по смыслу и по словам, текст всегда берёт из Mongo. Почему так -
ADR-009; когда факты пишутся сами и когда идёт обслуживание - `memory-in-pauses.md`.

`gateway/rag.py` (`RAGStore`), слова - `gateway/lexical.py`, Mongo - `gateway/repos/memory_repo.py`, поиск на
входе хода - `gateway/recall.py`.

## Запись

| Что | Как |
|---|---|
| правда | документ `_memories` в Mongo: полный текст, стабильный `_id`, теги, счётчики доступа, `last_used_at` |
| оглавление | один факт - несколько точек Qdrant (коллекция `context`): summary и каждый вопрос из `questions` (фасеты, приём в духе HyDE); вопросов нет - одна точка по summary |
| дубль | tool `remember` и `POST /sam/memory` сначала зовут `find_duplicate`: фасет факта с косинусом не ниже `DEDUP_SIM_THRESHOLD` (0,92) к summary нового - второй записи нет, ответ «Уже помню» с текстом записи; извлечение фактов перед сжатием отсекает повтор своим порогом `SAM_MEMORY_DUP_SCORE` (`memory-in-pauses.md`); запись скиллов сверяет свои записи по имени скилла |
| правка | `update` меняет только Mongo; вектор пересобирается при `reindex=True` |
| удаление | `forget_by_id`, `forget_by_query` удаляют из Mongo и Qdrant |

## Поиск

1. Вектор: запрос -> эмбеддинг -> Qdrant, кандидатов `top_k` x 3, лучший фасет на факт; порог 0,5
   (`DEFAULT_SCORE_THRESHOLD`) режет только эту ветку. Свой порог для фактов с меткой - `SAM_RAG_TAG_MIN`
   («метка=порог» через запятую, по умолчанию `skill=0.7`: верные совпадения со скиллами 0,8-1,0, ложные до 0,64).
2. Слова: BM25 по тексту, summary и тегам фактов из Mongo (`SAM_RAG_LEXICAL`, по умолчанию включено; читает до
   `SAM_RAG_LEXICAL_SCAN` 5000 фактов): имя одним словом вектор почти не различает.
3. Слияние RRF. Запрос из одного слова (`SAM_RAG_SHORT_QUERY_TOKENS`) - сначала найденное по словам.
4. Текст и признак архива - из Mongo по `mongo_id`; архивные факты отбрасываются.
5. MMR (λ 0,7) убирает почти одинаковые факты из выдачи.

Пока эмбеддер грузится, поиск идёт одними словами. Эмбеддер - `paraphrase-multilingual-MiniLM-L12-v2` (384),
отдельным процессом `gateway/embedder_service.py` на `SAM_EMBEDDER_URL` (`127.0.0.1:10204`, SAM-172); процесс не
отвечает - модель грузится в шлюзе (около 30 с). Нет модели и процесса - `EmbedderUnavailableError`, размерность не
совпала с коллекцией - `DimensionMismatchError`, нулевой вектор вместо ошибки не пишется.

Ход, критик, воркер и tools памяти зовут поиск через `asyncio.to_thread` (SAM-74). На входе хода - голос, чат,
inject - поиск идёт до выбора основной модели со сроком `VOICE_RAG_TIMEOUT_S` (1,5 с); опоздавшие факты модели вне
шлюза приходят тиком `rag` (`recall.py`, SAM-101).

## Обслуживание

| Метод | Что |
|---|---|
| `expand_facets` | добавить вопросы-фасеты факту |
| `prune_dead_facets` | убрать фасеты без попаданий старше 90 дней |
| `prune_unused` | удалить факты без использования дольше 90 дней |
| `reindex_all` | пересобрать все векторы из Mongo: смена модели эмбеддингов, расхождение Qdrant и Mongo |

Ночная консолидация (`gateway/dream.py`, `memory-in-pauses.md`) зовёт `prune_dead_facets` при `SAM_DREAM_APPLY=1`;
у остальных методов вызывающего в коде нет, их зовут из Python руками:

- `expand_facets` задуман шагом консолидации (SAM-22: поднять часто вспоминаемые), но ему нужны вопросы от LLM, а
  факты в Mongo SAM-22 разрешает менять только после живой проверки ночного запуска;
- `prune_unused` тоже задуман в консолидации, SAM-22 называет шаг архивом невостребованных, а метод факты удаляет
  (`forget_by_id`);
- `reindex_all` - ручной инструмент ADR-009 на смену эмбеддера и расхождение индекса, расписания ему не нужно.

## Проверка

`tests/test_rag.py`; повтор при записи - `tests/test_memory_write_api.py`.

## Не закрыто

- Qdrant догоняет Mongo только при `reindex_all`; Change Streams не используются.
- `expand_facets` и `prune_unused` без вызывающих до живой проверки консолидации (SAM-22); `prune_unused` перед
  подключением - выбор автора: архив, как в SAM-22, или удаление, как в коде.

## «Запомни» и возврат к прошлому (ADR-027, 15 окт)

- Просьба «запомни» раскладывается на две части: содержание - фактом в долгую память (`remember`), он живёт независимо
  от окна и находится поиском; намерение («напомнить про доктора», «вернёмся к утренней теме») - в канал мыслей
  (`docs/features/compression.md`, «Два канала»), который сжимается отдельно от разговора и не вытесняется новыми
  беседами.
- Напоминание к сроку ставит себе будильник - крон или workflow на нужное время: в тишине основная модель просыпается
  только от входящих.
- Подробности сжатой беседы основная модель поднимает из архива (`sessions_archive`) инструментом «поднять историю» по
  теме или отрезку времени; сейчас поиск по памяти архив не охватывает (SAM-224).
  Поднятое не копируется в историю: в MongoDB пишется одна запись-ссылка «вернулись к прошлому разговору» с отрезками архива, журнал остаётся линейным без дублей. При сборке контекста шлюз вставляет поднятые отрезки из архива в окно по времени, между несмежными кусками - маркеры пропуска; расширение - окно в N сообщений сверх обычного (`SAM_RECALL_WINDOW`). Модель видит старую и текущую беседу в оригинале и может их связать. Сжатию всё равно, свои это сообщения или поднятые и сколько тем загружено: оно сжимает окно по обычным правилам и дописывает сводки в MongoDB одну за другой, расширение сходит на нет само.
