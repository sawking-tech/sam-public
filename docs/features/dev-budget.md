# Бюджет тяжёлой работы SAM

Лимиты защищают бюджет от быстрого расхода на агентные задачи и оставляют средства на бытовые запросы.
Расход считается в рублях по скользящим окнам; цены берутся из записей вызовов или книги цен.

## Лимиты

| Период или потолок | Переменная окружения | По умолчанию |
|---|---|---|
| Час | `SAM_DEV_HOUR_RUB` | 15 ₽ |
| Рабочее окно | `SAM_DEV_WINDOW_H`, `SAM_DEV_WINDOW_RUB` | 5 часов, 40 ₽ |
| Сутки | `SAM_DEV_DAY_RUB` | 150 ₽ |
| Неделя | `SAM_DEV_WEEK_RUB` | 0 ₽ (выключено) |
| Месяц тяжёлой работы | `SAM_DEV_MONTH_RUB` | 3000 ₽ за 30 дней |
| Общий потолок месяца | `SAM_MONTHLY_BUDGET_RUB` | 5000 ₽ за 30 дней |

`spent_heavy` учитывает расход роли `worker` по источникам `SAM_BUDGET_SOURCES` (по умолчанию `polza`),
исключая сессии лёгких задач. Записи без определённой цены не учитываются. Общий месячный расход включает все роли.

## Тяжёлая работа и очередь

`is_heavy` относит задачу к тяжёлым, если классификатор определил уровень 3 или выше либо заказанный пул шагов
больше `SAM_LIGHT_TASK_STEPS` (по умолчанию 10). Бытовые и лёгкие задачи, включая создание агентов для них,
идут без ограничения окнами тяжёлой работы.

При достижении лимита тяжёлая задача сохраняется в `_deferred_tasks` с исходными параметрами. Шедулер проверяет
очередь каждые `SAM_DEFERRED_EVERY_S` секунд (по умолчанию 60) и запускает старейшую задачу, когда её пропускает
проверка лимита. Младшие задачи не обгоняют старейшую, если она не проходит проверку.

## Ступени и восстановление

Ступень по месячному остатку тяжёлого бюджета определяется в `stage`:

| Ступень | Условие и действие |
|---|---|
| `normal` | Остаток не ниже `SAM_DEGRADE_SAVING` (по умолчанию 35%): обычная работа. |
| `saving` | Остаток ниже `SAM_DEGRADE_SAVING` (0,35): экономия. |
| `minimal` | Остаток ниже `SAM_DEGRADE_MINIMAL` (0,15) или исчерпан: тяжёлая работа остановлена. |
| `floor` | Остаток счёта не выше `SAM_HOUSEHOLD_FLOOR_RUB` (500 ₽) либо общий расход достиг общего потолка за вычетом этого резерва: тяжёлая работа остановлена. |

`target_stage` учитывает резерв раньше доли тяжёлого бюджета. `Stager` ухудшает ступень сразу, а повышает на одну
ступень после непрерывной выдержки `SAM_RECOVER_HOLD_MIN` (по умолчанию 30 минут); затем для следующего повышения
нужна новая выдержка. При аварии `gate` снимает ограничения тяжёлой работы.

## Состояние

`GET /sam/usage/dev-budget` возвращает состояние бюджета.
