# Цикл агента и вызовы tools

Главный агент, воркер и агент Cortex крутятся в одном цикле: модель - вызовы tools - результаты - модель, пока не
будет ответа. Вызовы приходят нативно или текстом, их разбирает один слой. Почему так - ADR-006.

`gateway/agent_loop.py` (`run_agent_loop`, зависимости - `AgentLoopDeps`), адаптеры - `gateway/llm_client.py`,
схемы и сообщения под поставщика - `gateway/provider_transform.py`, разбор текста - `gateway/tool_text_parse.py`.

## Адаптеры

`LLM_ADAPTER` в `.env` или `POST /sam/llm/switch` (`python -m gateway.cli llm switch <адаптер>`):

| Адаптер | Что делает |
|---|---|
| `openai` (по умолчанию) | прямой AsyncOpenAI с нативными tools: у всех поставщиков SAM OpenAI-совместимый адрес; формату `harmony` (gpt-oss) нативные tools не передаются |
| `custom` | тот же AsyncOpenAI и проверка синтаксиса вызовов из текста (мета-формат, `LLM_TEXT_TOOLS`) |
| `litellm` | через litellm, для поставщика без OpenAI-совместимого адреса |
| `auto` | `openai`; после `LLM_PARSE_FAIL_THRESHOLD` (3) провалов разбора подряд на локальной модели - `custom` |

Разбор вызовов из текста идёт на любом адаптере: Qwen через litellm писал вызов текстом там, где ждали нативный.
Форматы - Harmony, `<tool_call>`, `[tool_call: ...]`, голые Python-вызовы, GLM-4, Gemma 4; каждый - разбор с тестом.
`provider_transform` чистит схемы tools под поставщика (Gemini отвечал 400 на часть JSON Schema) и сообщения
(особенности Claude, Mistral, Gemini).

## Защита цикла

| Что | Как |
|---|---|
| тот же tool 3 раза подряд (у шлюзов `mcp_call` - тот же вызов целиком: имя и аргументы) | подсказка «Ты вызываешь X 3-й раз подряд; результаты выше - используй их или ответь», событие `loop_guard` |
| тот же tool 5 раз подряд (у шлюзов `mcp_call` - тот же вызов целиком: имя и аргументы) | следующий вызов модели с `tool_choice="none"`: только ответ |
| опрос без прогресса | тот же вызов с тем же результатом `SAM_NO_PROGRESS_LIMIT` (3) раз, и вперемешку с другими - системная строка «ответь тем, что известно», событие `no_progress`, дальше `tool_choice="none"` |
| повтор вызова | вызов с теми же именем и аргументами за один прогон цикла не исполняется повторно, кроме `READONLY_TOOLS` (`tools/list`, `screenshot`, `get_windows`, `get_audio_state`, `list_allowed_directories`, `read_file`, `search_web`) |
| невыданный tool | инструмент, которого модели не показали, не исполняется: ответ «Инструмента X нет» |
| лимит шагов | `max_turns` и пул шагов задачи (`workers.md`); кончились - служебный ответ «Превышен лимит шагов агента» |
| `[STOP_WORKER]` | tool вернул маркер - цикл заканчивается последним ответом воркера |
| инъекции | на каждом шаге цикл забирает сообщения для сессии из шины (`pop_inject`, ADR-004) и добавляет их с меткой `[INJECT]` |
| обрезанный вызов | ответ упёрся в предел (`finish_reason=length`), а вызов не разобрался: нативный - с битыми аргументами, текстом - не нашёлся вовсе. Вызов не исполняется, обрезанный текст не уходит ответом; модель получает причину с пределом и советом: «раздели аргументы на несколько вызовов или пиши короче», у `app_make` и `app_update` - «раздели файл - app_make с частью, остальное app_update или несколько файлов» (`split_hints`, `gateway/tools/apps.py`). Имя инструмента у вызова текстом берётся из обрезки, если оно там есть. В ходе только с ответом обрезанный текст уходит как есть |

## Предел ответа модели

| Переменная | По умолчанию | Ход |
|---|---|---|
| `SAM_LOOP_MAX_TOKENS` | 8192 | модель может вызвать инструмент (`tool_choice="auto"`) |
| `SAM_LOOP_MAX_TOKENS_TEXT` | 2048 | только ответ (`tool_choice="none"`): после 5 одинаковых вызовов подряд или опроса без прогресса |

Вызов `app_make` со страницей 5 КБ (код с кириллицей) занимает 1,6-1,9 тыс. токенов аргументов, страница 8 КБ -
около 3 тыс.; GLM с рассуждением (zai) тратит тот же предел и на него. При прежних 2048 такой вызов обрезался в 12 из
14 попыток живого прогона 14 окт (SAM-210). Против залипания модели на повторе работают штрафы повторов
(`provider_transform.sampling_for_provider`, кроме Gemini), предел только ограничивает цену такого сбоя. Выше
8192 предел не поднимать без проверки поставщика: у gemini-2.0-flash потолок вывода 8192, больший `max_tokens` -
ответ 400. Пределы читаются при старте шлюза.

## Регистрация tool

Класс `BaseTool` с `@register_tool` (из qwen_agent берутся только они), имя в `MAIN_TOOL_NAMES` или
`WORKER_TOOL_NAMES`, функция в `TOOL_IMPL` (`gateway/agent.py`). Сама функция - `*_impl(params, deps)` в
`gateway/tools/` с зависимостями параметрами.

## Не закрыто

- Новая модель с новым форматом вызова: вызов не разобран, текст уходит ответом, пока не добавлен разбор.
- Разбор текста может принять вызов в обычном ответе текстовой модели за настоящий.

Шлюзовой инструмент `mcp_call` открывает сотни инструментов устройства под одним именем, поэтому его повтор считается по вызову целиком (`agent_loop.GATEWAY_TOOLS`, `loop_signature`). Счёт по имени остался защитой от разноса с тех времён, когда у агента не было пула шагов и квот; сейчас работу агента ограничивает пул шагов и `request_steps` (ADR-022), и пять разных команд подряд законная работа, а не цикл (28 окт: 52 из 53 принудительных завершений приходились на `mcp_call`, часть агентов ушла с итогом «Готово.»).
