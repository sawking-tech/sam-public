# features

Из чего собирается сценарий: восемь подсистем, каждая со своим набором порогов, переменных и переключателей.
Здесь отвечают на вопрос «что даёт и как включить», читатель — тот, кто ставит SAM задачу и настраивает стенд.
Как устроено внутри и почему так — [architecture](../architecture/README.md), сценарии целиком — в
[scenario](../scenario/README.md).

| Подпапка | Что даёт | Главные механизмы |
|---|---|---|
| [voice](voice/README.md) | SAM слышит и говорит, одним процессом на весь дом | опознание голоса по профилю, перебивание, две модели в разговоре: быстрая отвечает, основная поправляет |
| [memory](memory/README.md) | помнит людей, место, договорённости между ходами | факт в Mongo как правда, Qdrant как оглавление, гибридный поиск по смыслу и словам |
| [automation](automation/README.md) | работает без реплики человека | workflow файлом в репозитории, условие вызова модели кодом без LLM, очередь push с подтверждением |
| [execution](execution/README.md) | чужой код и страницы, которые живут | песочница-контейнер без секретов, живые приложения в своём контейнере, общий каркас страниц |
| [safety](safety/README.md) | что SAM не выполнит | четыре уровня проверки до исполнения инструмента, судья на модели, блокировка вызова |
| [money](money/README.md) | сколько стоит и когда останавливается | учёт токенов по роли, цена из таблицы, лимиты по скользящим окнам |
| [checks](checks/README.md) | проверка без живых людей | прогон на наборе случаев из истории, трасса этапов хода в миллисекундах |
| [character](character/README.md) | как SAM себя ведёт | когда действует сама, когда спорит, порядок ответа, объяснение с ценой и доводом |

Пороги всех подсистем живут в их разделах; сводной таблицы переменных нет намеренно, каждая — там, где работает.
