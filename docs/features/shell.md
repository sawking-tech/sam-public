# Каркас страниц SAM

Один каркас на все страницы: монитор, страница приложений, радар, приложение в рамке. Полоса с навигацией, колонка
контента, выдвижная панель. Своё у страницы - только содержимое колонки и что лежит в панели.

Файлы - `gateway/static/shell/`. `shell.css` и `panel.js` скопированы из `DotNetSolutionKit/site` (cc7660d) без
правок: `panel.js` двигает всю рамку вместе с полосой, ширина из `--panelw` и `--maxw`, тема auto/light/dark,
сторона панели, выбор запоминается под префиксом `sam`. У копий своя только шапка-комментарий, `tests/test_shell.py`
сверяет их с источником, когда репозиторий лежит рядом. Своё у SAM - `sam.css` (токены, шрифт рамки, кнопка
закрытия) и `shell.js` (сборка рамки и API).

## Раскладка

```
┌──────────── полоса .bar: прилипает сверху, высота --barh 53px ──────────────────────────────┐
│ [◆ SAM]  Приложения  Монитор  Радар …   │   статус страницы   │   индикаторы  [☾] [☰]       │
└─────────────────────────────────────────────────────────────────────────────────────────────┘
        ┌──────── колонка .wrap: до --maxw 1120px, по центру, поля --gut 20px ────────┐
        │   содержимое страницы                                                      │
        └────────────────────────────────────────────────────────────────────────────┘
                                                      ┌─ панель #sidebar --panelw 272px ─┐
                                                      │ выдвигается, сдвигает рамку      │
                                                      └──────────────────────────────────┘
```

- **Полоса одна на всех страницах.** Слева лого (ведёт на домашний экран приложений) и навигация: «Приложения»,
  затем закреплённые. По центру статус текущей страницы одной строкой. Справа индикаторы страницы, кнопки темы и
  панели. Человек находит одно и то же на одном месте, переход не перестраивает взгляд.
- **Колонка по центру, до 1120 px** (1200 от 1600 px окна). Шире образца (920): ленте монитора нужна колонка
  телеметрии слева, а длину строки реплики держит сама реплика (`max-width: 80ch`), не колонка. На 1440 px при
  открытой панели лист сдвигается на 112 px, и у колонки остаётся поле.
- **Узкий экран (до 900 px): панель поверх.** Механика образца сдвигает лист на ширину панели, и страница уезжает
  за край. Здесь панель ложится поверх листа со своей стороны, лист стоит на месте.
- **Панели - возможность, раскладку выбирает страница.** Каркас умеет панель слева, справа, обе и вкладки внутри:
  `SAMShell.openPanel({side, tab, title, ...})`. По умолчанию одна правая панель с вкладками: две открытые на
  1440 px забирают 544 px, и колонка сжимается меньше 920.
- **Панель - всё вторичное.** Настройки, задачи, подробности, фильтры, удаление. Панель одна за раз, Esc закрывает.
- **Линии сплошные:** граница колонки и панели - одна линия `--line` на всю высоту, без разрывов между секциями.

## Цвета

Раскладка от DotNetSolutionKit, палитра «ночной дом» от радара: SAM - внимание, которое не спит. Токены
(`gateway/static/shell/sam.css`) перекрывают токены образца (`--ground`, `--panel`, `--line`, `--text`, `--muted`,
`--focus`), сама копия `shell.css` не тронута.

| Токен | Что |
|---|---|
| `--r-ink` | фон, ночь |
| `--deck` | поверхности: колонка, панель, карточки; второй уровень - смесь `--deck` и `--wire` |
| `--wire` | линии и границы |
| `--haze` | вторичный текст, служебное, инструменты и воркеры |
| `--r-text` | текст |
| `--amber` | человек в разговоре, фокус |
| `--ice` | SAM, «сейчас», живая связь, идёт ход |
| `--lilac` | голос и мысль SAM (на радаре - `--pet`) |
| `--alarm` | ошибка, обрыв, STOP |

Светлая тема «дом днём» - те же имена: бумага, линии и текст чернилами, акценты того же тона, темнее в OKLCH до
4.5:1. Свечение (`--glow`) только у живых точек. Своих цветов у страниц нет.

## Подключение

```html
<link rel="stylesheet" href="G/static/shell/shell.css"><link rel="stylesheet" href="G/static/shell/sam.css">
<script src="G/shell/config.js"></script><script src="G/static/shell/boot.js"></script>
<script src="G/static/shell/shell.js" defer data-page="apps"></script>
```

`G` - адрес шлюза, у страниц шлюза пусто. `shell.js` переносит содержимое страницы в рамку (`#sam-content`) и
подгружает `panel.js`. Без атрибутов страница получает всё: рамку, навигацию, тему, панели. Навигацию отдаёт
`/shell/config.js` (`gateway/shell_config.py`: приложения, монитор, радар, если поставлен). Страница на другом порту
(радар `:8010`) подключает каркас со шлюза.

Переопределение - атрибуты тега `shell.js`, только если странице нужно своё:

| Атрибут | Что делает |
|---|---|
| `data-shell="off"` | без каркаса, своя полноэкранная страница; API панелей ничего не делает |
| `data-bar="off"` | без полосы |
| `data-panelw="360"` | ширина панели, px |
| `data-maxw="4000"` | ширина колонки, px; шире окна - панель всегда выдвижная и сдвигает страницу |
| `data-fill="1"` | контент занимает окно под полосой, прокрутка внутри страницы (монитор) |

## API панелей

`window.SAMShell`:

- `openPanel({title, node | src | srcdoc, onClose})` - панель с содержимым: узел своей страницы, адрес или разметка
  во фрейме с `sandbox="allow-scripts"`. Одна панель за раз: новая заменяет прежнюю.
- `closePanel()` - закрыть; фокус возвращается туда, где был до открытия. Закрывают и Esc, и кнопка в шапке.
- `setDefaultPanel(title, node)` - что панель показывает без вызова; по умолчанию список страниц SAM.
- `connectApp(iframe, slug)` - принимать вызовы панелей от приложения в этом фрейме.

На широком экране панель стоит в поле сбоку всегда (так устроен `panel.js`); вызов меняет её содержимое, закрытие
возвращает содержимое по умолчанию.

## Монитор

```
┌─ полоса ─────────────────────────────────────────────────────────────────────────────────────┐
│ [◆ SAM] Приложения Монитор Радар │ ведёт: llm, сжатие voice: 23 без сжатия, 31 мин назад │ ● 290 [⛔ STOP] [☾] [☰] │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
    ┌─ колонка ──────────────────────────────────────────────────────────────────┐
    │   ↑ старые сообщения подгружаются при прокрутке вверх                       │
    │   последние сообщения - сразу, внизу                                        │
    ├─────────────────────────────────────────────────────────────────────────────┤
    │   [ поле ввода                                              ] [Отправить]   │
    └─────────────────────────────────────────────────────────────────────────────┘
   панель (кнопка ☰ или кнопки полосы): Задачи | Настройки | Фильтр событий
```

- **Последние сообщения сразу внизу, старые подгружаются вверх.** Монитор открывают, чтобы увидеть, что
  происходит сейчас; ждать загрузку всей истории ради последней строки - потеря.
- **Без мигания.** Новое событие дописывается в конец, список не перерисовывается: перерисовка сбивает прокрутку и
  взгляд.
- **Обновление страницы - без пустого экрана.** Шлюз шлёт первой порцией последние `SAM_MONITOR_FIRST_PAGE` (60)
  событий, остальное - прокруткой вверх. Последние 80 событий вкладка держит в `sessionStorage` 10 минут: после F5
  они встают в первом кадре уже внизу, снимок шлюза дописывает только новое по `ts_iso` (проверено 15 окт: 55
  строк из кеша, 55 после снимка, 145 после прокрутки вверх).
- **Подгрузка вверх без потерь.** Порция кончается на записи с временем и `_id`, следующая начинается строго раньше
  этой пары: записи одной миллисекунды (вызов и итог инструмента) границу не теряют. Индексы (`timestamp`, `_id`) и
  (`session_id`, `timestamp`, `_id`) у `sam.sessions` и `created_at` у `sam.tasks` шлюз создаёт при старте.
- **Статус по центру полосы** (кто ведёт, сжатие) - состояние страницы, его смотрят мельком. **Индикаторы и STOP
  справа у кнопок** - действия и сигналы управления.
- **Задачи и настройки в панели.** Список задач после F5 берётся из `GET /sam/tasks`: события `task_*` в историю не
  пишутся, и раньше панель после обновления была пустой.
- **Лента одной сессии или агента.** Селектор внизу выбирает, чья лента видна и куда уходит реплика; «все сессии» -
  реплика уходит в `homepc`, и это написано у поля ввода. Выбор адресата переживает F5 (`localStorage`), агент как
  адресат не восстанавливается. «Глаз» задачи открывает ленту агента и адресата не меняет; закончившийся агент
  отмечен у поля ввода: «фраза оживит агента <имя>». Записи выбранной сессии старше общей ленты подгружаются её
  курсором (`/sam/monitor/history?session=`) и уходят при возврате.
- **Проверка guard - пометкой на вызове.** `guard_check` и `guard_pass` не строки, а пометка `guard ✓` у строки
  вызова (по сессии и `call_id`); отдельной строкой идёт только `guard_block`. У вызова, разобранного из текста
  (`text_<шаг>_<номер>`, id повторяются), проверка приходит раньше вызова: пометка ждёт его не дольше минуты, блок
  её снимает. Длинные аргументы и мета-блоки показаны началом, щелчок разворачивает целиком. Итог вызова шлюз шлёт
  до `SAM_MONITOR_RESULT_CHARS` (4000) знаков.

Монитор - `gateway/static/monitor.html`, модули - `gateway/static/monitor/`. Его `#main` стал `#mon-main`
(`#main` - рамка каркаса), свои цвета `--m-text` и `--m-muted`, монитор тёмный при любой теме. Логика разбора
событий и ленты - `tests/js/monitor` (node --test через `tests/test_monitor_modules.py`).

## Страница приложений

```
        ┌─ колонка ──────────────────────────────────────────────────────────────────┐
        │  Закреплённые                                                              │
        │  [▣ Монитор] [◎ Радар] [▦ График]                                          │
        │  Остальные                                                                 │
        │  [▦ Доска] [▤ Тренажёр]                                                    │
        └─────────────────────────────────────────────────────────────────────────────┘
   плитка: лого SVG или скриншот, имя, точка состояния; на углу ⏸/▶ и ⚙
   ⚙ -> панель: описание, просьба, когда, адрес (сменить), закрепить, настройки, внизу «Удалить»
```

Плитка - лого или снимок, имя, точка: узнают по виду, читают одно слово. Приостановить - на плитке, остальное в
панели: частое действие под рукой, редкое и опасное глубже. Устройство приложений - `apps.md`.

## Радар и приложение в рамке

- **Радар** (`radar/static/presence.html`, сервис `:8010`) - карта дома шире колонки: страница переопределяет
  ширину, полоса и панель общие. Сцена на всё окно под стеклом полосы, подписи и отладка встают под полосу (класс
  `sam-shell`), свои цвета `--r-ink` и `--r-text`. Копия каркаса радару не нужна: шлюз и радар на одной машине, без
  шлюза страница всё равно не работает.
- **Приложение** - его страница во фрейме на всю колонку: `/apps/<slug>` (`gateway/app_view.py`). Поле `shell`
  манифеста переопределяет только атрибуты тега `shell.js` (`{off: true}`, `{bar: false, panelw: 360}`); имя и
  просьба подставляются текстом с экранированием. Шестерёнка и панель по умолчанию - описание приложения и ссылка на
  страницу приложений. `/apps/<id>` отвечает 308 на `/apps/<slug>`, `/apps/radar` - 307 на радар.

Приложение вызывает панели клиентом `/static/shell/app-client.js` без своего кода панелей:
`SAMApp.openPanel({title, path})` - своя страница по пути внутри приложения, `SAMApp.openPanel({title, html})` -
разметка, `SAMApp.closePanel()`. Клиент шлёт `postMessage` родителю; `bridge.js` принимает сообщение, только если
его источник - окно фрейма этого приложения и origin `null` (страница в песочнице CSP) или шлюза. Путь -
относительный, без схемы и `..`. Содержимое от приложения идёт фреймом, в DOM каркаса разметка приложения не
попадает.

## Проверка

`tests/test_shell.py` (сверка копий с образцом, атрибуты, API панелей), `tests/test_monitor_modules.py` и
`tests/js/monitor` (модули монитора), `tests/integration/test_live_surface.py` (живая проверка монитора и
приложений). Снимки страниц на 375, 768 и 1440 px в обеих темах: полоса и колонка совпадают по положению, линии
сплошные, своих серых нет, консоль без ошибок.
