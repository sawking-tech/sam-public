# Каркас страниц SAM

Общий каркас для монитора, страницы приложений, радара и приложений: полоса с навигацией по страницам SAM, рамка и
выдвижная панель. Рамка и панель скопированы как есть из `DotNetSolutionKit/site` (cc7660d): `panel.js` (панель
сдвигает всю рамку вместе с полосой, ширина из `--panelw` и `--maxw`, тема auto/light/dark, сторона панели, выбор
запоминается под префиксом `sam`), `boot.js`, каркасная часть `site.css` (строки 1-257) в `shell.css`. У копий
своя только шапка-комментарий; `tests/test_shell.py` сверяет их с источником, когда репозиторий лежит рядом.
Своё у SAM - `sam.css` (шрифт рамки, кнопка закрытия, переопределения) и `shell.js` (сборка рамки и API).

Файлы - `gateway/static/shell/`, шлюз раздаёт их по `/static/shell/...`, навигацию - скриптом `/shell/config.js`
(`gateway/shell_config.py`: приложения, монитор, радар, если поставлен; все - страницы шлюза). Страница на другом
порту (радар :8010) подключает каркас со шлюза.

## Страницы в каркасе

- Монитор (`gateway/static/monitor.html`): `data-fill="1"`, `data-maxw="4000"` - занимает окно под полосой, панель
  выдвижная. Логика монитора та же; его `#main` стал `#mon-main` (`#main` - рамка каркаса), свои цвета - `--m-text`
  и `--m-muted` (у каркаса `--text` и `--muted` меняются с темой), монитор тёмный при любой теме. Ссылки «радар» и
  «приложения» из его шапки ушли в полосу; прежний `/apps-panel` шлюза ведёт на `/apps`.
- Радар (`radar/static/presence.html`, сервис :8010): каркас со шлюза, адрес подставляет `presence_api` (хост
  запроса и порт `SAM_SERVER`). Копия каркаса при сборке радара не нужна: шлюз и радар
  на одной машине, а страница без шлюза всё равно не работает - навигация и панели ведут на него. Сцена остаётся
  на всё окно под стеклом полосы (её координаты считаются от окна), подписи и отладка встают под полосу (класс
  `sam-shell`), свои цвета - `--r-ink` и `--r-text`. Своя панель отладки радара пока своя: перенос карточек места и
  человека в API панелей каркаса - следующий шаг.
- Страница приложений `/apps` (`docs/features/apps.md`, «Страница приложений»), приложение (`/apps/<slug>`, ниже).

## Подключение

```html
<link rel="stylesheet" href="G/static/shell/shell.css"><link rel="stylesheet" href="G/static/shell/sam.css">
<script src="G/shell/config.js"></script><script src="G/static/shell/boot.js"></script>
<script src="G/static/shell/shell.js" defer data-page="apps"></script>
```

`G` - адрес шлюза, у страниц шлюза пусто. `shell.js` переносит содержимое страницы в рамку (`#sam-content`) и
подгружает `panel.js`. Без атрибутов страница получает всё: рамку, навигацию, тему, панели.

Переопределение - атрибуты тега `shell.js`, только если странице нужно своё:

| Атрибут | Что делает |
|---|---|
| `data-shell="off"` | без каркаса, своя полноэкранная страница; API панелей ничего не делает |
| `data-bar="off"` | без полосы |
| `data-panelw="360"` | ширина панели, px |
| `data-maxw="4000"` | ширина колонки, px; шире окна - панель всегда выдвижная и сдвигает страницу |
| `data-fill="1"` | контент занимает окно под полосой, прокрутка внутри страницы (монитор) |

## API панелей

`window.SAMShell`:

- `openPanel({title, node | src | srcdoc, onClose})` - панель с содержимым: узел своей страницы, адрес или
  разметка во фрейме с `sandbox="allow-scripts"`. Одна панель за раз: новая заменяет прежнюю.
- `closePanel()` - закрыть; фокус возвращается туда, где был до открытия. Закрывают и Esc, и кнопка в шапке.
- `setDefaultPanel(title, node)` - что панель показывает без вызова; по умолчанию - список страниц SAM.
- `connectApp(iframe, slug)` - принимать вызовы панелей от приложения в этом фрейме.

На широком экране панель стоит в поле сбоку всегда (так устроен `panel.js`); вызов меняет её содержимое, закрытие
возвращает содержимое по умолчанию.

## Приложение в каркасе

Адрес приложения - `/apps/<slug>` (`gateway/app_view.py`, `gateway/static/app_view.html`): каркас вокруг, страница
приложения - во фрейме `/apps/<slug>/` с CSP sandbox, как раньше. Без поля `shell` в манифесте приложение получает
всё: каркас, навигацию, тему, панели. Поле `shell` переопределяет только атрибуты тега `shell.js`
(`{off: true}`, `{bar: false, panelw: 360}`); имя и просьба подставляются текстом с экранированием. Шестерёнка на
странице и панель по умолчанию на широком экране - описание приложения и ссылка на страницу приложений, где
настройки, закрепление и удаление. `/apps/<id>` отвечает 308 на `/apps/<slug>`, `/apps/radar` - 307 на радар.

Приложение вызывает панели клиентом `/static/shell/app-client.js` без своего кода панелей:
`SAMApp.openPanel({title, path})` - своя страница по пути внутри приложения, `SAMApp.openPanel({title, html})` -
разметка, `SAMApp.closePanel()`. Клиент шлёт `postMessage` родителю; `bridge.js` принимает сообщение, только если
его источник - окно фрейма этого приложения и origin `null` (страница в песочнице CSP) или шлюза. Путь -
относительный, без схемы и `..`. Содержимое от приложения идёт фреймом, в DOM каркаса разметка приложения не
попадает.
