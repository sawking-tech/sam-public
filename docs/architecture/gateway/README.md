# gateway

Входы шлюза и что они делают с ходом: кто ведёт ход, как идёт цикл, из чего собирается промпт, каким форматом
модель вызывает инструмент.

Все четыре файла описывают одно: главный агент, воркер и агент Cortex крутятся в **одном цикле** — модель, вызовы,
результаты, снова модель, пока не будет ответа. Роль меняет только набор инструментов и лимиты, а не сам механизм.

| Файл | Механизм |
|---|---|
| [main-model.md](main-model.md) | кто ведёт ход: модель роутера (за ней может стоять Cortex за ACP) или внешний CLI-прокси для стендов без ключа. Выбор по приоритету из списка моделей, с инерцией и сменой без рестарта; любой вход — голос, чат, workflow — сходится в одну очередь |
| [agent-loop.md](agent-loop.md) | цикл: адаптеры `openai`/`custom`/`litellm`/`auto`, защита от петель (тот же вызов 3 и 5 раз, опрос без прогресса, повтор за прогон), предел ответа, регистрация инструмента через `@register_tool` |
| [prompt.md](prompt.md) | промпт из трёх слоёв: душа в Mongo (доходит со следующего хода), `SAM.md` в репозитории (после рестарта), `data/SAM.md` вне git (сразу). Засев души, версии и откат, правка мимо сервиса не проходит |
| [tool-formats.md](tool-formats.md) | как модель пишет вызов: `harmony`, `<tool_call>`, нативный OpenAI. Хранение нейтрально ролью `tool_call`, под модель форматируется при чтении истории |

Адаптер и формат — разные настройки: `LLM_ADAPTER` говорит, чем ходить, формат вызова определяется по имени модели.
Разбор текста идёт на любом адаптере.
