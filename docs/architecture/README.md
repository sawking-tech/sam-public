# architecture

Как SAM работает внутри. Здесь отвечают на вопрос «как устроено и почему так», читатель — тот, кто чинит или меняет
SAM. Что включается и какие пороги крутить — в [features](../features/README.md), сценарии — в
[scenario](../scenario/README.md).

| Подпапка | Что внутри |
|---|---|
| [gateway](gateway/README.md) | входы шлюза, основная модель, цикл агента, сборка промпта, форматы вызовов |
| [agents](agents/README.md) | кто работает: воркеры шлюза, агенты за ACP, пул шагов, каналы к создателю |
| [context](context/README.md) | память хода: сжатие истории и хранилище Mongo с Qdrant |
| [llm](llm/README.md) | выбор модели под задачу, отказы поставщиков, паузы |
| [stand](stand/README.md) | процессы стенда, надзор, что делать при падении блока |
| [access](access/README.md) | ключ API, ключ привилегий, секрет команд |

Разделение ролей и куда система идёт — [brain-map](../brain-map.md). Решения и причины — [ADR](../adr/README.md).
