# architecture

Как SAM работает внутри: шесть подсистем и карта файлов. Здесь отвечают на вопрос «как устроено и почему так»,
читатель — тот, кто чинит или меняет SAM. Что включается и какие пороги крутить — в [features](../features/README.md),
сценарии целиком — в [scenario](../scenario/README.md).

| Подпапка | Что решает | Основа |
|---|---|---|
| [gateway](gateway/README.md) | кто ведёт ход и как модель зовёт инструменты | один цикл агента для всех ролей, вызовы нативно и разбором текста, промпт из трёх слоёв |
| [agents](agents/README.md) | кто выполняет работу | три исполнителя: воркер шлюза в процессе, агент Cortex за ACP, агент кода как внешний CLI; права от создателя |
| [context](context/README.md) | что модель видит на ходе и как это не растёт | скользящее окно сводок, каскад слияния, архив; Mongo — правда, Qdrant — оглавление |
| [llm](llm/README.md) | какую модель берёт вызов | вид задачи, цепочка запасных поставщиков, паузы после отказа у клиента |
| [stand](stand/README.md) | из каких процессов состоит стенд | два надзора друг за другом, перезапуск по командной строке, лог на компонент |
| [access](access/README.md) | кто попадает в шлюз | два ключа разного назначения, проверки Host, Origin, Content-Type, секрет команд |
| [structure.md](structure.md) | что где лежит | крупные блоки, средние, дерево папок, зависимости между ними |

Разделение ролей и куда система идёт — [brain-map](../brain-map.md). Решения и причины — [ADR](../adr/README.md).
