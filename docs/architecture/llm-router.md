# Выбор модели и отказы поставщиков

Каждый вызов LLM называет вид задачи; роутер выбирает поставщика по виду и идёт по цепочке запасных, клиент
помнит отказы поставщиков. Почему так - ADR-002. Кто основная модель SAM (Claude Code или модель шлюза) - отдельный
выбор, `main-model.md`.

`gateway/llm_router.py` (`get_best_llm`), `gateway/llm_client.py` (`make_llm_call`), классификация отказов -
`gateway/provider_transform.py` (`classify_error`).

## Виды задач

| Вид | Кто просит | Как выбирается |
|---|---|---|
| `fast` | голосовой ход | быстрая модель `LLM_FAST_SOURCE` (по умолчанию `lmstudio`) и `LLM_FAST_MODEL` (для LM Studio по умолчанию `qwen/qwen3-30b-a3b-2507`, только уже загруженная: загрузка на ходу - около 30 с); `off` или недоступна - как `turn`; совпала с основной - ответ считается ответом основной (SAM-170) |
| `turn` | текстовый ход | `SAM_AGENT_BACKEND=acp` и агент настроен - агент за ACP (ADR-022); иначе как `default` |
| `planning` | планирование, структурный JSON | Anthropic (Claude Haiku) -> Gemini Flash -> LM Studio -> Claude Code CLI -> DashScope |
| `default` и прочие | остальные вызовы | LM Studio -> Gemini Flash -> DashScope |

- `LLM_SOURCE` принудительно выбирает поставщика для всех видов, кроме `fast` и `turn` с агентом за ACP; поставщик
  недоступен - строка в лог и обычная цепочка. Поставщики: `lmstudio`, `gemini`, `dashscope`, `anthropic`, `zai`,
  `openrouter`, `polza`, `claude_code`, `acp`.
- Поставщик в цепочке есть, когда задан его ключ (`GEMINI_API_KEY`, `ANTHROPIC_API_KEY`, `DASHSCOPE_API_KEY`), LM Studio
  отвечает или CLI `claude` запускается. `zai` - только через `LLM_SOURCE` или `LLM_FAST_SOURCE` (`ZAI_BASE_URL`,
  `ZAI_MODEL` `glm-5.3-flash`).
  Агрегаторы `openrouter` и `polza` (OpenAI-совместимый вход) работают так же: только через `LLM_SOURCE` или
  `LLM_FAST_SOURCE`, ключ `OPENROUTER_API_KEY` / `POLZA_API_KEY` и id модели `OPENROUTER_MODEL` / `POLZA_MODEL` обязательны
  (без модели поставщик недоступен, в лог строка, что задать), адрес - `OPENROUTER_BASE_URL` / `POLZA_BASE_URL`.
- Claude Code CLI - последний запасной: он тратит лимиты подписки.
- LM Studio: модель по id `LMSTUDIO_MODEL`; без него - единственная загруженная, несколько - LM Studio пропускается, причина
  в `/health` (SAM-57). Модель меньше 4 млрд параметров по имени пропускается. Формат подсказки (`harmony`, `glm`,
  `qwen` и другие) определяется по имени модели.

## Рассуждение

SAM - система реального времени, поэтому уровень рассуждения задаётся ролью вызова в одном месте
(`gateway/reasoning.py`, его зовёт `llm_client.make_llm_call` на каждой попытке, SAM-226):

| Роль | Уровень |
|---|---|
| ход основной модели, сводка сжатия, шаг ask workflow, судья реплики и ответа (`judge`), непомеченный вызов | минимум |
| воркер, судья вызовов инструментов (`guard`) | низкий |

Уровень роли меняет `SAM_REASONING_<РОЛЬ>` (`min` или `low`).

Способ - по поставщику. LM Studio выключает рассуждение полем `chat_template_kwargs.enable_thinking`, DashScope -
`enable_thinking`; низкого уровня у них нет, на нём рассуждение остаётся включённым. У z.ai рассуждение glm-5.3 не
выключается, effort уровня - `SAM_REASONING_ZAI_MIN` и `SAM_REASONING_ZAI_LOW` (по умолчанию `low`). Где рассуждение идёт,
к пределу ответа добавляется `SAM_REASONING_RESERVE_TOKENS` (2048): иначе оно съедает весь предел и ответ приходит
пустым. Поставщикам из `SAM_REASONING_PROMPT_SOURCES` (по умолчанию `zai`) на минимальном уровне в конец системной
части добавляется инструкция рассуждать минимально и отвечать сразу.

Сводки истории идут на служебную модель `get_service_llm`: загруженная в LM Studio qwen (`SAM_SERVICE_LLM_SOURCE`,
`SAM_SERVICE_LLM_MODEL`, `off` - основная), иначе основная модель роутера.

## Отказы

| Отказ | Что делает клиент |
|---|---|
| 429 | пауза поставщика 2, 5, 10, 20 с - растёт с каждым 429 подряд, ответ поставщика счёт обнуляет; замена по цепочке сразу |
| 401, 403 или текст об отказе ключа | пауза поставщика на час (3600 с), замена |
| 5xx и молчание поставщика (код 504) | пауза 10 с, замена |
| контекст не влез | без паузы и без замены: ошибка уходит вызывающему, контекст надо урезать |
| прочее | пауза 60 с, поставщик пропускается до конца этого вызова, замена |
| замены нет или роутер вернул пропущенного | `RuntimeError` «Все LLM провайдеры недоступны» |

Сроки молчания (не замерены, с запасом над обычным ходом): ответ без потока `LLM_CALL_TIMEOUT_S` (120 с), первый кусок
потока `LLM_FIRST_TOKEN_TIMEOUT_S` (60 с), пауза между кусками `LLM_DELTA_TIMEOUT_S` (30 с). Срок считается после
очереди к местам: одновременных вызовов не больше `LLM_CONCURRENCY` (4), освободившееся место первым получает
голосовой ход (ADR-010). Попытка, которая уже отдала часть ответа и упала, зовёт `on_reset`: следующая стримит ответ
с начала.
