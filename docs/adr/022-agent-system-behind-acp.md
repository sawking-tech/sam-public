# ADR-022: Агентная система отделена от шлюза, шлюз - клиент ACP, внешний агент за флагом в прокси-режиме

**Статус:** принято 12 окт 02:06 (разделить систему, подключиться через Hermes или OpenCode); 12 окт дополнено - свой агент Cortex (раздел ниже), агенты в Cortex сделаны (SAM-133); открытые вопросы ниже


## Контекст

Ход, инструменты, фоновые агенты, сценарии, судьи и монитор живут в одном процессе шлюза (`gateway/`, порт 8000).
Упал процесс - SAM не может ни перезапустить себя, ни сказать об этом; любой перезапуск ради скилла, флага или
правки рвёт разговор, монитор и фоновые задачи. Ведущий Claude Code подключён своим протоколом поверх файлов шины
(ADR-012, ADR-018) - по сути та же схема «сервер агента и клиенты».

Разбор, схема и таблицы -.

## Решение

1. Мозг (цикл агента, рассуждение) отделяется от периферии (шлюз, голос, MCP) и клиентов (монитор, TUI).
2. Граница между шлюзом и мозгом - открытый протокол ACP (Agent Client Protocol, JSON-RPC по stdio): шлюз
   держит агента подпроцессом, передаёт ему MCP-агрегатор SAM в сессии, пересказывает `session/update` в шину
   голоса и монитора, на `session/request_permission` отвечает судьёй SAM.
3. Флаг `SAM_AGENT_BACKEND` выбирает, кто ведёт ход: `sam` (нынешний цикл в шлюзе, по умолчанию до замера),
   `acp` (внешний агент; команда запуска - из конфига). Откат - одной строкой, как с сетью радара.
4. Первые внешние реализации - Hermes Agent (Python, полный ACP в `acp_adapter/`) и OpenCode (ACP поверх своего
   сервера). Какая станет по умолчанию - после замера задержки голоса и размера запроса.
5. Внешний агент работает в прокси-режиме: его инструменты файлов, терминала и веба, крон, скиллы и память
   выключены; действие - только через MCP SAM и её судей; расписание - только у SAM (ADR-020); скиллы SAM
   подаёт в ход шлюз; контекст хода держит память SAM (ADR-008, ADR-009, ADR-015), свой контекст агента - запас
   на случай её падения.
6. Взаимный надзор: шлюз поднимает агента (подпроцесс, смерть видна по stdio), надзиратель без модели поднимает
   периферию, планировщик ОС - всё.

## Рассмотренные варианты

**Оставить всё в шлюзе.** Отклонён: процесс шлюза - единственная точка отказа. Теряем: простоту одного процесса.

**Свой сервер агента сразу (Python или C# модулем AVOX).** Отложен: граница ACP позволяет поставить его третьим
значением флага позже, не трогая шлюз. Теряем: на время - полный контроль над размером запроса и циклом.

**Свой протокол между шлюзом и мозгом (HTTP + WebSocket).** Отклонён: ACP уже даёт сессии, поток, разрешения и
MCP клиента, и его говорят Hermes и OpenCode. Теряем: удалённый режим ACP по HTTP пока в работе у протокола.

## Риски и что с ними делаем

| Риск | Что происходит | Чем закрыт |
|---|---|---|
| Каркас агента шлёт большой промпт и все описания инструментов | Голос медленнее, токены дороже | Замер до и после; по умолчанию не ставится без замера |
| Реализация не даёт выключить свои инструменты или крон | Два планировщика, действия мимо судей | Проверка прокси-режима на каждой реализации; не выключается - не ставится по умолчанию |

| Агент упал посреди хода | Ход без ответа | Шлюз видит закрытый stdio, ход завершается ошибкой, агент поднимается заново |
| Состояние в памяти процесса шлюза | Перезапуск мозга теряет разговор | Перенос очереди фраз, агентов и контекста хода в Mongo и шину - шаги перехода |

## Решение 12 окт: свой агент Cortex за той же границей

Автор, 05:03-05:19: свой агент тоньше внешних, со своими инъекциями, общением агентов и памятью-надсистемой;
имя - Cortex. У внешних каркасов нет общения агентов и инъекций в ход, история раздутая, сжатие своё.

- Cortex - сервер ACP на Python в `cortex/acp/` (модуль `cortex` по docs/brain-map.md), запускается подпроцессом той
  же командой, что и внешний агент. Шлюз и клиент ACP не меняются: Cortex - ещё одна реализация за флагом `acp`,
  Hermes и OpenCode остаются для сравнения (SAM-125).

  протоколов нет.
- Ход ведёт тот же цикл `agent_loop`, что и в шлюзе. Инструменты - только из MCP сессии: прокси-режим без настройки.
- Инструмент, который меняет машину, идёт через запрос разрешения, то есть через судью SAM; чтение - без судьи.

## Агенты в Cortex (решения автора 10-12 окт)

Собрано из `gateway/tools/agents.py` (SAM-91, 10 окт 00:03-00:46) и журнала (12 окт 02:40, 04:47-04:55, 14:34).
Сделано 12 окт (SAM-133): агент Cortex создаётся маршрутом и инструментом MCP `sam`; каркас по умолчанию - воркер
шлюза, пока Cortex не прошёл живой прогон. Создание, права, каналы, пределы и переменные - `docs/features/agents.md`.

- **Где.** Агент создаётся в нашей обёртке - сессией Cortex, а не задачей шлюза. Ради этого и пишется свой агент: у
  внешних каркасов нет общения агентов и инъекции сообщений.
- **На ход.** Агент создаётся под задачу; создатель заранее находит нужные инструменты и передаёт их список, лишний
  поиск остаётся внутри агента.
- **Метка сложности.** Кто ставит задачу, тот выставляет `smart`, `medium` или `weak`; по метке - модель из конфига,
  пусто - выбор роутера.
- **Права.** Инструменты агента выдаёт создатель, и не шире своих прав. Связь с создателем есть при любых правах.
- **Каналы связи.** Отчёт создателю (`report_status`), вопрос создателю (`ask_creator`): создатель отвечает в сессию
  агента `task:<id>`, агент продолжает; сообщение другому агенту (`send_to_agent`); реплика в идущий ход (`_sam/inject`).
- **Независимость от каркаса.** Агент не привязан к одному исполнителю: основная модель (или создатель) выбирает, чем он
  работает, из доступного на стенде - свой Cortex, Claude Code, OpenCode, Hermes - и какой моделью. Выбор лежит в параметрах
  `spawn_agent` (каркас и метка сложности), список доступных - в конфиге и в `list_capabilities`. Права, каналы связи и
  барьеры SAM одинаковы для любого каркаса.
- **Сверх выданного.** Агент может спросить, есть ли инструмент (`tool_search` видит и невыданные, с пометкой «нужно
  разрешение»), и попросить право (`request_permission`: инструмент и зачем); создатель выдаёт или отказывает.

Края - где прежние правила противоречили друг другу или молчали:

- **Пустой список прав.** Сейчас пустой `tools` у `spawn_agent` даёт все инструменты воркера - это шире прав создателя.
  Стало: пусто - только каналы связи и `tool_search`; остальное - явным списком или запросом права. У Cortex пустая
  выдача отклоняется, у воркера шлюза пустой список по-прежнему даёт все его инструменты.
- **Живёт задачу, а не ход.** «На ход» - создаётся под задачу хода; агент живёт, пока задача не закрыта, ход создателя
  может кончиться раньше. Итог приходит создателю следующим входом (`[TASK_DONE]`), как сейчас.
- **Создатель кончился.** Вопрос и запрос права уходят по цепочке создателей вверх к ближайшему живому, в конце - к
  основной модели. Нет ответа за срок из конфига - агент продолжает без него и пишет в отчёт, на чём остановился
  (у Cortex срок из конфига, затем задача закрывается итогом последнего хода).
- **Агент создаёт агента.** Права ребёнка - не шире прав родителя; запрос права ребёнка решает родитель, а чего у
  родителя нет - он пересылает своему создателю. Метку сложности выставляет создатель, глубину ограничивает конфиг.
  Ширину тоже: уровень считается от основной модели (нулевой). Агент основной модели создаёт не больше
  одного агента, тот - ни одного. Агент не знает, что мог бы больше: создав ребёнка, он теряет `spawn_agent`, а у
  последнего уровня этого инструмента нет вовсе, даже в описаниях. Шлюз перепроверяет пределы по своей записи задачи.
- **Шаги - пул на дерево.** Шаг - одно обращение агента к модели: его прикидывают этапами, токены
  прикинуть нельзя. Создатель передаёт прикидку `steps`, агент в первом же ответе оценивает задачу сам
  (`estimate_steps`, отдельного шага на оценку нет), пул - меньшая из оценок. Ребёнку пул выделяется из остатка
  родителя, родитель узнаёт свой остаток: лимит не обойти, создавая агентов вниз. На доле пула агент получает
  подсказку; не хватило - `request_steps` с причиной, создатель решает сам: выдать из своего остатка (`grant_steps`),
  отказать или забрать работу и доделать (не хватит ему - просит выше). Ход только с вызовами каналов шага не
  тратит, у таких вызовов своя квота на задачу (c32bea2). Числа и переменные - `docs/features/workers.md`.
  Просьба о шагах без ответа не остаётся: модель в шлюзе получает её своим ходом, и текст
  хода уходит агенту ответом; создатель вне шлюза выдаёт шаги через `grant_agent_steps` MCP `sam`
  (`POST /sam/agents/{id}/steps`, с ключом привилегий). Агент с кончившимся пулом ждёт ответа на просьбу до срока
  вопроса; без выдачи задача закрывается частичным итогом: последний статус, вызов, на котором встал, свежие итоги
  инструментов и причина остановки.
- **Кому писать.** Создателю - всегда. Другому агенту - только из списка, который дал вызывающий при создании
  (`POST /sam/agents` и `create_agent`, параметр `peers`; право выдаётся как `agent:<id>`), или после запроса этой привилегии (`request_permission` с именем
  агента и зачем), решает создатель или выше по цепочке. Иначе любой агент управлял бы чужой задачей.
- **Барьер не обходится.** Право, выданное создателем, не снимает барьеров SAM: привилегированный вызов по-прежнему
  требует ключа в ходе, судья проверяет опасное, политика `deny` сильнее выдачи. Агент идёт вне хода человека и
  ключа назвать не может: на привилегированный вызов он получает отказ «правка ядра агенту без права запрещена» с
  тем, что делать вместо (разбор, план и diff - создателю), а не просьбу назвать ключ (SAM-212, 15 окт). Маршруты, которые создают агентов,
  выдают права и меняют модель (`POST /sam/agents`, `/sam/agents/{id}/grant`, `/sam/main-model`, `/sam/llm/switch`),
  требуют ключа привилегий даже с этой машины (SAM-177); ключ передаёт только MCP `sam` ведущего, канал агента его
  не получает (`docs/features/agents.md`).
- **Голосовой ход.** У голосового хода свои инструменты нарочно урезаны (скорость, ADR-010), но агента он создаёт с
  правами основной модели: отбирает нужное и передаёт списком. Сейчас `spawn_agent` списка инструментов не
  принимает, воркер получает свой набор `WORKER_TOOL_NAMES`; список передаёт только `POST /sam/agents`.

## Матрица возможностей агента (12 окт)

Каждая строка - возможность, которую создатель включает агенту. Сейчас у воркеров шлюза часть есть, в Cortex - цель
пункта `cortex-workers`.

| Агент может | Что значит, если включено | Плюсы | Минусы | По умолчанию |
|---|---|---|---|---|
| Спрашивать создателя (`ask_creator`) | вопрос уходит создателю, ответ приходит в сессию агента, агент продолжает | не гадает, где не хватает контекста | ждёт ответа; создатель отвлекается; без срока может повиснуть | включено всегда, срок из конфига |
| Отчитываться создателю (`report_status`) | промежуточный и итоговый статус создателю | видно, что делает и где застрял | лишние входы создателю, токены | включено всегда |
| Общаться с другим агентом (`send_to_agent`) | сообщение и совместная работа с агентом из списка вызывающего или по выданной привилегии | агенты делят работу без посредника | путаница ролей, петли переписки, чужая задача под чужим влиянием | только список от вызывающего; остальные - запросом привилегии |
| Создавать своих агентов | дети с правами не шире своих, глубина из конфига | дробит большую задачу | дерево растёт, расход моделей, сложнее отследить | выключено, кроме главного |
| Просить дополнительное право (`request_permission`) | запрос инструмента с причиной, решает создатель или выше по цепочке | права растут по нужде, а не заранее | задержка на решение; цепочка до основной модели | включено |
| Искать невыданные инструменты (`tool_search`) | видит весь список с пометкой «нужно разрешение» | знает, что вообще возможно | тянется к лишнему, больше запросов прав | включено |
| Действовать на машине (shell, файлы, браузер, git на запись) | вызовы через судью SAM и политику | реальная работа на устройствах | цена ошибки - изменения на машине; судья - лишний вызов модели | только явной выдачей |
| Читать и писать память SAM | поиск по памяти, запись фактов | помнит дом и людей, копит знание | мусор в памяти, утечка личного другому агенту | чтение - да, запись - явной выдачей |
| Говорить с человеком напрямую | его текст звучит голосом SAM | быстрее, без пересказа | голос дома разных агентов, спор с главным, выдумка вслух | выключено: говорит главный; у агента быстрого голоса включено - его текст звучит |
| Принимать реплику в идущий ход (`_sam/inject`) | новое от человека или создателя видно на следующем шаге | поправка без перезапуска задачи | сбивает план агента посреди шага | включено |
| Жить дольше хода создателя | задача идёт в фоне, итог - следующим входом создателю | долгие задачи не держат разговор | итог приходит позже, контекст разговора уже другой | включено |
| Воскрешаться (`spawn_agent` с тем же именем и устройством, SAM-38) | агент продолжает прежнюю сессию с её историей, а не начинает заново; оживает и закончивший задачу, пока не умер по сроку | не теряет сделанное, дешевле повтора | тянет старые ошибки и устаревший контекст; два создателя оживляют одного агента | включено, сессия хранится в Mongo |
| Быть отменённым (`cancel_agent`) | создатель или основная модель останавливает агента, все или по id | лишняя работа и петли гасятся сразу | недоделанное теряется, если агент не успел отчитаться | у создателя и основной модели всегда |
| Видеть другие задачи (`list_agents`) | список идущих агентов, их имена и статусы | не плодит дубли, находит, кого оживить | шум в контексте; опрос списка в петле (12 окт главный крутил list_agents) | у главного; у агентов - выключено |
| Получать сообщения от создателя (`send_to_agent` в его сессию) | ответ на вопрос или новая вводная посреди работы | агент правится на ходу | вводная перебивает текущий шаг | включено всегда |
| Запускаться по расписанию или событию (шаг workflow `tool: spawn_agent`, ADR-020) | агента ставит не реплика человека, а workflow | проактивность: проверки и задачи без просьбы | агенты без человека - расход моделей и действия без свидетеля | только из файла workflow |
| Умирать по сроку (TTL задачи, `gateway/tasks.py`, срок продлевается при старте) | старый агент без дела сам удаляется вместе с сессией | не копятся зомби-задачи и их сессии | умерший уже не воскресится; долгая тихая задача может не дожить | включено, срок из конфига |
| Работать на выбранном каркасе (Cortex, Claude Code, OpenCode, Hermes) | создатель называет каркас, агент запускается им; права и каналы связи те же | задача идёт тем инструментом, который лучше подходит; SAM не зависит от одного каркаса | у каркасов разные возможности (у внешних нет инъекции и общения агентов), больше мест для поломок | цель - Cortex; сейчас воркер шлюза, Cortex - `SAM_AGENT_FRAMEWORK` или параметром `framework` |
| Модель по метке сложности | `smart`, `medium`, `weak` -> модель из конфига | дешёвая модель на простое | слабая модель на непростом ошибается | `medium` |

Барьеры SAM (ключ привилегий, судья, политика `deny`) действуют при любой выдаче: возможность агента их не снимает.

## Открытые вопросы

- Как Hermes говорит с нашими моделями (GLM через zai, Qwen в LM Studio) - проверяется пробой.
- Монитор и TUI: пересказ шлюза или поток `/event` сервера агента напрямую.
- Claude Code ведущим: свой протокол шины или неофициальный адаптер ACP по подписке.
- Надзиратель: свой процесс или менеджер служб Windows.

## Последствия

| Обязывает | Что даёт |
|---|---|
| Ход через ACP идёт тем же контрактом для любой реализации | Агент меняется флагом, шлюз не трогается |
| Действие агента - только через MCP SAM и судей | Безопасность не зависит от реализации |
| Расписание, скиллы и память - у SAM | Один планировщик и одна память при любом агенте |

| Запрещает или ограничивает | Чем платим |
|---|---|
| Свои инструменты, крон и скиллы внешнего агента выключены | Готовые возможности каркасов не используются |
| Внешний агент по умолчанию - только после замера | Переход медленнее |
