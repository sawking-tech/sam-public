# ADR-015: Фоновая работа с памятью идёт в паузах разговора; порог сжатия в токенах, факты извлекаются перед сжатием

**Статус:** принято


## Контекст

Сжатие запускается при 14 сообщениях (`gateway/compression.py:26-29`, `gateway/runner.py:309`), то есть по
числу, а не по объёму, и зовёт LLM на той же GPU, пока идёт живой ответ (ревью 8 окт). Флаг «идёт сжатие»
живёт в памяти процесса (`compression.py:166`), ошибка уровня 1 не ловится. Факт попадает в долгую память,
только если модель вызвала `remember` (`gateway/tools/memory.py`); при сжатии факты из разговора в Qdrant не
извлекаются. Заготовки консолидации есть (`expand_facets`, `prune_dead_facets`, `gateway/rag.py:302,350`),
запускать их некому (SAM-22). mem0 извлекает факты на каждом ходе, openclaw сбрасывает важное перед
сжатием (матрица 8 окт).

## Решение

Работа с памятью - сжатие истории, извлечение фактов, консолидация - идёт только в паузе разговора, с отменой
при новой фразе и записью итога одной операцией; в ходе и по счётчику сообщений она не запускается.
Порог сжатия - в токенах несжатой истории; жёсткий потолок сжимает и без паузы. Факты из удаляемого куска
извлекаются перед удалением, только добавлением, с источником. Состояние работ - в Mongo, не в памяти
процесса. Ворота, пороги и переменные - `docs/architecture/compression.md`.

Сделано: ворота простоя, порог и потолок в токенах, постановка сжатия при записи реплики в историю, извлечение
фактов перед удалением куска (за `SAM_MEMORY_AUTOWRITE`, по умолчанию выключено), ночная консолидация (за `SAM_DREAM`).
Не сделано: отмена начатого сжатия новой фразой, состояние работ в Mongo (флаг сжатия - в памяти процесса), слияние
повторов и забывание в консолидации (SAM-22). Механика сжатия - `docs/architecture/compression.md`.

## Рассмотренные варианты

**Порог по числу сообщений и сжатие параллельно ответу (было до SAM-62, ADR-008).** Отклонён: длина сообщений не
видна, GPU делится с живым ответом. Теряем на выбранном пути: сжатие сразу после порога.

**Извлечение фактов на каждом ходе, как mem0.** Отклонён: лишний вызов LLM рядом с живым ответом. Теряем:
факт попадает в память только к ближайшей паузе.

**Только явный `remember` (было до SAM-63).** Отклонён: факты теряются при сжатии. Теряем: контроль модели над
тем, что записано.

**Взять mem0 библиотекой (Apache-2.0).** Отклонён: у SAM своя модель памяти (ADR-009), вторая копия фактов
разошлась бы с Mongo. Теряем: готовый код извлечения и обновления фактов.

## Риски и что с ними делаем

| Риск | Что происходит | Чем закрыт |
|---|---|---|
| Пауз нет | Контекст растёт | Жёсткий потолок |
| Отмена посреди записи | Половина итога | Архив до удаления (ADR-008), итог одной операцией |
| Модель выдумала факт | Ложь в памяти | Источник у факта, `forget`; консолидация; механически не закрыт |
| Факт гостя записан как факт домашнего | Путаница в памяти | Поле `who` (ADR-011); у неузнанного голоса не закрыт |

## Последствия

| Обязывает | Что даёт |
|---|---|
| Любая фоновая работа с памятью проходит ворота простоя | Живой ответ не делит GPU со сжатием и консолидацией |
| Порог сжатия считается в токенах | Контекст ограничен тем, что реально занимает место |
| Перед удалением куска истории из него извлекаются факты | Сказанное в разговоре переживает сжатие |
| У автоматического факта есть источник | Ошибочный факт находится и удаляется |

| Запрещает или ограничивает | Чем платим |
|---|---|
| Запускать сжатие и консолидацию во время речи (кроме потолка) | В длинном разговоре без пауз контекст растёт до потолка |
| Править или удалять факт при извлечении (только добавление) | Ошибочные и устаревшие факты копятся до консолидации |
| Держать состояние фоновых работ в памяти процесса | Запись в Mongo на каждый запуск |
