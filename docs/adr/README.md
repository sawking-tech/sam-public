# Архитектурные решения SAM

ADR - решение о дизайне системы: правило или парадигма, которые навязываются подходу к разработке и меняют
скелет SAM - границы модулей, поток данных, контракты между частями, выбор технологии. На ADR опирается
будущая работа.

- ADR описывает текущее состояние и куда система движется. Пока набор устанавливается, решение меняется правкой
  существующего ADR на месте, новые ADR ради поправок не заводятся. Когда автор скажет, что набор устоялся,
  новое решение пишется новым ADR, который отменяет прежний. История - в git и журнале.
- Номера идут подряд; после удаления оставшиеся перенумеровываются, ссылки вне журнала правятся.
- Как работает фича (правила, пороги, переменные, файлы) - описание в `docs/features/`; ADR ссылается на него
  одной строкой.

Проверка: в «Последствиях» есть обязательство и запрет для будущего кода. Нечего записать - это фича.

Что берём в v1 и что нет -, раздел «v1: берём / не берём сейчас».

## Формат

Файл `NNN-краткое-имя.md`, на
русском.

```
# ADR-00N: <решение одной строкой>
**Статус:** предложено | принято
## Контекст                  что есть и почему типовой путь не годится; факты с файлом и строкой
## Решение                   что делаем - коротко; механика фичи - ссылкой на docs/features
## Рассмотренные варианты    **Название.** Отклонён: причина. Теряем на выбранном пути: ...
## Риски и что с ними делаем таблица: риск | что происходит | чем закрыт
## Последствия               две таблицы: обязывает | что даёт; запрещает или ограничивает | чем платим
```

Числа - только замеренные или из кода. Архитектуру утверждает автор: новый ADR получает статус «предложено»,
реализация начинается после «принято». Отклонённый ADR удаляется, причина остаётся в журнале.

Проверены и оставлены задачами:

- Модель по id, нативные tools, без размышлений на голосовом пути - SAM-57 (уточнение ADR-002 и ADR-006).
- Heartbeat и очередь своих реплик - SAM-49.
- Скиллы по запросу - SAM-61.
- Агенты кода по голосовой просьбе - SAM-60 (инструмент `claude_delegate` уже есть, ADR-005 задаёт, что он у воркера).
- Guard (паттерны и LLM-судья для рискованных tools) - механика есть (`gateway/guard.py`), но развилок в истории не видно и запретов для кода она не задаёт сверх ADR-005; описана в README.
