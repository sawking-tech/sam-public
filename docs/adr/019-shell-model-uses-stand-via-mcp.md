# ADR-019: Модель из shell пользуется стендом через MCP стенда, подключённый один раз её штатным способом

**Статус:** принято


## Контекст

Сессия Claude Code в роли основной модели (ADR-018) действовала средствами терминала: свой shell, свои файлы, свои
агенты. Инструменты SAM (память, агенты, устройства) живут в шлюзе и доступны только модели внутри шлюза. Факт
о дне рождения сессия записала вручную вызовом `remember_impl` из Python
(SAM-94).

Автор, 10 окт (журнал):
- 01:07: «Надо забыть про свой терминал, про свои функции, и в первую очередь использовать функции стенда. Свои
  функции - второй приоритет».
- 01:09: «для открытых через shell моделей, когда стенд в режиме прокси работает, это правильный путь: они должны
  сами конфигурироваться и использовать свои нативные инструменты, например MCP-сервер».
- 01:10 (SAM-91): подключение MCP к модели - настройка заранее, один раз, описанная в README;
  start_sam его не автоматизирует.

Агрегатор стенда уже отдаёт MCP по Streamable HTTP: `POST http://localhost:3000/mcp` (`mcp/mcp_aggregator.py`).

## Решение

Модель, открытая через shell (Claude Code, OpenCode), пользуется стендом через MCP-сервер стенда, подключённый
её штатным способом один раз; инструменты стенда - первый приоритет, средства терминала - второй. Инструменты SAM,
нужные основной модели, выставляются в MCP стенда. Как подключить - `docs/features/stand.md`, раздел «MCP стенда».

Сделано: подключение `sam-stand` у Claude Code 10 окт 01:08 (`.mcp.json`, вне git) - 62 инструмента устройств;
приоритет инструментов стенда в роли сессии (7bdd2dd). Инструменты SAM для основной модели вне шлюза - отдельный
MCP-сервер `sam` (`mcp/sam_server.py`, 6e62235, SAM-175), stdio рядом с `sam-stand` в `.mcp.json`: `memory_search`,
`remember`, `create_agent`, `answer_agent`, `grant_agent_tool`, `push_ack`, `switch_main_model`, каждый - вызов REST
шлюза. Маршрутам создания агентов, выдачи прав и смены модели сервер передаёт ключ привилегий (ADR-022).

## Рассмотренные варианты

**HTTP-запросы модели к шлюзу под каждое действие.** Отклонён: модель пишет запросы руками, у
другой модели из shell свой способ. Теряем: ничего, REST шлюза остаётся для людей и скриптов.

**start_sam сам прописывает MCP в конфиг модели.** Отклонён автором 01:10. Теряем: стенд на новой машине
без ручного шага.

## Риски и что с ними делаем

| Риск | Что происходит | Чем закрыт |
|---|---|---|
| MCP стенда не подключён у модели | Модель действует терминалом | Шаг настройки в `docs/features/stand.md`; проверка - tools/list |
| Агрегатор упал | Инструменты стенда пропали | Вкладка поднимает агрегатор; `/health` шлюза показывает `mcp` down |
| Привилегированный инструмент без ключа команд | Действие без подтверждения | Для инструментов SAM в MCP - не закрыт, гард шлюза их не видит; SAM-91 |

## Последствия

| Обязывает | Что даёт |
|---|---|
| Инструмент SAM для основной модели выставляется в MCP стенда | Любая модель из shell получает его одинаково |
| Подключение описано в документации как разовый шаг | Новая машина настраивается по описанию |

| Запрещает или ограничивает | Чем платим |
|---|---|
| Основной модели действовать терминалом там, где есть инструмент стенда | Инструмента нет - ждём его в MCP или идём терминалом вторым приоритетом |
| Автонастройку MCP в start_sam | Ручной шаг на каждой машине и у каждой модели |
