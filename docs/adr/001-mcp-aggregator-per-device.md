# ADR-001: Действия на ПК идут через MCP-агрегатор устройства

**Статус:** принято


## Контекст

SAM управляет компьютерами в доме: окна Windows, браузер, файлы, процессы. Готовые MCP-серверы для этого
(playwright, filesystem, desktop automation) работают через stdio и запускаются на той машине, которой
управляют. Gateway живёт отдельно: по плану на сервере Aspire, ПК подключаются клиентами (CLAUDE.md,
«Железо»). Нужен способ дать gateway инструменты нескольких stdio-серверов на удалённом ПК.

## Решение

На каждом ПК работает `mcp/mcp_aggregator.py`: поднимает stdio MCP-серверы из `mcp/configs/local.json`
(конфиг этого ПК) и отдаёт их инструменты на одном HTTP-порту (:3000, `MCP_PORT`). `mcp/client_agent.py` регистрирует устройство и шлёт
heartbeat (`/sam/client/register`, `/sam/client/heartbeat`). Gateway зовёт инструмент вызовом
`mcp_call(device, tool, args)` через HTTP-клиент `gateway/mcp_client.py`.

| Что | Где | Основание |
|---|---|---|
| агрегатор вместо mcp-proxy | `mcp/mcp_aggregator.py`, `mcp/client_agent.py` | 9f83553 |
| вызов одного сервера по очереди, таймаут вызова и очереди по 30 с (`MCP_CALL_TIMEOUT_S`, `MCP_QUEUE_TIMEOUT_S`) | `mcp_aggregator.py:72-118` | код, SAM-76 |
| набор серверов - конфигом устройства | `mcp/configs/local.json` | 9f83553, 5eab7f7 (SAM-47) |

## Рассмотренные варианты

**mcp-proxy на клиенте.** Отклонён в 9f83553 («replace mcp-proxy with aggregator»); причина в истории не
записана.

Других вариантов в истории и документах не видно.

## Риски и что с ними делаем

| Риск | Что происходит | Чем закрыт |
|---|---|---|
| Долгий вызов держит сервер | Следующие вызовы к тому же серверу ждут: `asyncio.Lock` на сервер | Таймаут 30 с на вызов; голосовой путь v1 в MCP не ходит (ADR-010) |
| ПК выключен или агрегатор упал | `mcp_call` падает по сети | `presence_score` по heartbeat, `get_devices` показывает онлайн; `wake_device` будит по WoL |
| Ключи сторонних MCP | Попадут в конфиг | Ключи только через env (SAM-47) |

## Последствия

| Обязывает | Что даёт |
|---|---|
| Новая возможность на ПК подключается MCP-сервером в конфиге устройства | Gateway не меняется ради новой программы на ПК; готовые серверы берутся как есть |
| Действие на ПК идёт вызовом `mcp_call` с именем устройства | Одно место для guard и логов всех действий на устройствах |
| Каждое устройство держит свой агрегатор и `client_agent` | Gateway знает, какие ПК онлайн, и не зовёт выключенные |

| Запрещает или ограничивает | Чем платим |
|---|---|
| Gateway не запускает процессы на ПК напрямую; исключение - `claude_delegate` на машине gateway (`gateway/tools/coding_agents.py`) | Лишний сетевой переход и процесс-агрегатор на каждом ПК |
| Один сервер выполняет один вызов за раз | Параллельные действия на одном сервере идут последовательно |
| Ответ инструмента - текст, склеенный из частей (`mcp_aggregator.py:85-90`) | Картинки и структуры приходят строкой |
