# ADR-016: Код, который пишет SAM, выполняется в контейнере без секретов и данных стенда; сеть - по запросу под файрволом

**Статус:** предложено; в коде. 9 окт (0e4ef27): `gateway/sandbox.py`, инструмент воркера `sandbox_run`, `GET /sandbox/<id>/<файл>`. 14 окт (8a5d383..6d87683): сеть по запросу под файрволом, журнал задачи, пакеты из PyPI и npm с OSV, копия с ПК, git clone, перенос в приложение и выгрузка на ПК, замок задачи, задача принадлежит сессии. 14 окт: быстрая проверка - тёплый контейнер сессии, `sandbox_exec`


## Контекст

Автор 9 окт 01:49-01:51: хочет у SAM песочницу, где она безопасно пишет код на Python и чём угодно ещё и
показывает результат, например отрисованный HTML; главное - изоляция: новый код выполняется отдельно и от
самой SAM, и от системы. Дальше на этом строятся домашние порталы (SAM-83).

Что есть: код сейчас идёт прямо на ПК. `claude_delegate` запускает Claude Code или OpenCode в папке
репозитория (`gateway/tools/coding_agents.py`, SAM-60), `run_command` и `powershell` идут через MCP-агрегатор
(`mcp/windows_control_server.py`) с судьёй guard по политике (SAM-79). Процесс gateway держит ключи
поставщиков в окружении, адреса Mongo и Qdrant и `.env`. Монитор (`gateway/static/monitor.html`) HTML не
отрисовывает. На ПК Docker 29.6.1 и образ `python:3.12-slim`.

Замер 9 окт на ПК: `docker run --rm --network none ... python:3.12-slim python m.py` - 0,68-0,73 с от вызова
до выхода; внутри uid 1000, окружение только образа (ни одной переменной gateway), запрос к 1.1.1.1 падает
`Network is unreachable`, файл, записанный в `/work`, виден на хосте.

## Решение

| Часть | Решение |
|---|---|
| Граница | Каждый запуск - новый контейнер `docker run --rm`; код не грузится в процесс шлюза и воркеров |
| Права | Без привилегий и capabilities, uid 1000, `no-new-privileges`, корень только для чтения, лимиты памяти, процессора, процессов и времени из env |
| Данные | Монтируется одна папка задачи; ни `.env`, ни данных SAM, ни Docker-сокета, ни переменных шлюза |
| Сеть | Нет по умолчанию. По запросу задачи - своя сеть песочницы с интернетом, а файрвол закрывает из неё дом, хост и сети Docker; правила ставятся перед каждым запуском с сетью, не встали - сети нет (дополнено 14 окт: автор - среда для чего угодно) |
| Образ | Свой, с закреплёнными версиями библиотек; только локальный, `start_sam.ps1` собирает (SAM-83) |
| Внутрь и наружу | Пакеты, копия с ПК, клон, выгрузка на ПК и перенос в приложение - только параметрами запуска, копией шлюза байтами без перехода по ссылкам, под замком задачи, строкой в журнале задачи; пакет - только точная версия после OSV; копия с ПК и выгрузка выключены, пока человек не задал папки в env (дополнено 14 окт) |
| Сессия задачи | Задача принадлежит сессии разговора, где её начали; чужая сессия получает отказ (дополнено 14 окт) |
| Быстрая проверка | Тёплый контейнер на сессию разговора, та же изоляция и всегда без сети; канал шлюза держит процесс, который кода не выполняет, ответ код подделать не может; зависание гасит только этот контейнер (дополнено 14 окт) |
| Показ | Файл задачи отдаётся с `Content-Security-Policy: sandbox allow-scripts`, монитор показывает его в `iframe sandbox`: страница не дотягивается до API шлюза и cookie ключа |

Модуль - `gateway/sandbox.py`: сборка команды и разбор путей отдельно от запуска процесса. Флаги, образы, параметры
запуска, журнал, настройки и замеры - `docs/features/execution/sandbox.md`.

Замер 14 окт: запуск в тёплом контейнере - медиана 2,8 мс против 0,79 с холодного.

## Рассмотренные варианты

**Подпроцесс на хосте с ограничениями (venv, job object, RestrictedPython).** Отклонён: процесс видит файлы
пользователя, сеть и окружение; ограничения Windows (job object) не закрывают файловую систему, а
RestrictedPython закрывает только Python. Теперь теряем: запуск без Docker и 0,7 с на старт контейнера.

**WSL Ubuntu как песочница.** Отклонён: WSL по умолчанию монтирует диски Windows (`/mnt/c`) и делит сеть с
хостом; изоляцию пришлось бы собирать руками. Теряем: Linux-окружение без Docker Desktop.

**Долгоживущий контейнер на все запуски.** Отклонён: код одного запуска оставляет процессы и файлы следующему,
падение одного роняет все. Теряем: тёплый интерпретатор и установленные между запусками пакеты. Тёплый интерпретатор вернулся в узком виде (14 окт): контейнер на одну сессию, без сети и файлов задачи, зависание гасит только его, состояние живёт только внутри беседы.

**gVisor, Firecracker, отдельная ВМ.** Отклонён для v1: на ПК Windows с Docker Desktop, ставить ещё один
рантайм - отдельная работа. Теряем: изоляцию ядра сильнее, чем у namespace-контейнера.

**Выполнять код агентами кода (SAM-60).** Отклонён как граница: агент кода работает на хосте в папке
репозитория, у него те же права, что у пользователя. Агент кода может работать внутри песочницы - это
следующий шаг, а не замена.

## Риски и что с ними делаем

| Риск | Что происходит | Чем закрыт |
|---|---|---|
| Побег из контейнера | Код получает хост | Без привилегий и capabilities, uid 1000, `no-new-privileges`, без Docker-сокета; ядро общее - остаётся риском уровня Docker |
| Зависание или форк-бомба | Контейнер жрёт ПК | Лимиты памяти, процессора и процессов; таймаут и `docker kill` |
| HTML из песочницы читает данные монитора | Утечка ключа, вызовы API от имени человека | CSP `sandbox` без `allow-same-origin`, `iframe sandbox`; cookie ключа `HttpOnly`, `SameSite=Strict` |
| Нужна сеть (pip install) | Код без пакетов | Пакеты - параметром `packages` из PyPI и npm с точной версией и OSV, установка отдельным запуском с сетью; базовое - в образе |
| Пакет или клон подменяет реестр или выполняет код при установке | Чужой код до проверки | Установка не читает папку задачи, pip только колёсами из `python -I`, npm с `--ignore-scripts`; клон без хуков, подмодулей и перенаправлений |
| Импорт или выгрузка задевают секреты ПК | Ключи и токены в задаче или поверх файлов ПК | Корни и папка экспорта - только из env, не корень диска, не домашняя, не папки SAM; секреты по маскам не копируются; выгрузка без перезаписи |
| Чужая задача по job id | Агент другой сессии запускает код в чужой задаче или переносит её в приложение | Задача принадлежит сессии, где её начали (`<id>.owner.json` вне `/work`, создаётся атомарно); `sandbox_run` и `from_job` другой сессии - отказ; задача без записи сессии достаётся первой обратившейся сессии со строкой в журнале; воркер получает сессию своего хода и оживляется по имени только в ней (дополнено 14 окт). Агенты основной модели вне шлюза (POST /sam/agents, MCP sam) идут от `SAM_AGENT_PARENT_SESSION` (voice) и делят задачи с голосовой беседой - так задумано: их создаёт модель этой беседы, путь закрыт ключом привилегий. Показ файлов в мониторе - по ключу доступа, как раньше |
| Тёплый контейнер держит состояние между запусками | Код одного запуска оставляет процессы и переменные следующему | Только той же сессии разговора; без сети и данных; зависание и простой гасят контейнер, потолок числа контейнеров; ответ после перезапуска говорит, что состояние потеряно (дополнено 14 окт) |
| Код с сетью ходит куда не надо | Утечка папки задачи, атака на дом | Дом и хост закрыты правилом всегда; секретов и данных стенда внутри нет; сеть - только на задачу по запросу |
| Сеть модель выдаёт себе сама (`network=internet`) | Код задачи с сетью выгружает её данные наружу при prompt injection | Файрвол закрывает дом и хост, но не выгрузку данных задачи наружу; пропускать ли internet через guard - решение автора, открыто |
| Правила файрвола слетели (перезапуск Docker) | Сеть песочницы без запретов | Правила ставятся перед каждым запуском с сетью, иначе сети нет |
| Docker не запущен | Песочница недоступна | Tool отвечает одной строкой, что делать; остальная SAM работает |
| Папки задач копятся | Диск | Папка задачи - результат, её смотрят в мониторе; уборка старых - отдельной задачей |

## Последствия

| Обязывает | Что даёт |
|---|---|
| Код, который SAM пишет для выполнения, запускается только через `gateway/sandbox.py` | Одна точка, где видно и ограничено, что выполняется |
| В контейнер не передаются переменные окружения и данные SAM | Ключи и память не утекают в код песочницы |
| Файлы песочницы отдаются только с CSP `sandbox` | Страница из песочницы не действует от имени монитора |
| Лимиты и сеть - настройки env с безопасными значениями по умолчанию | Ослабление изоляции - явное решение в `.env` |
| Файлы внутрь и наружу - только параметрами `sandbox_run` (`import`, `clone`, `export`) и `from_job` приложений, копией шлюза | Видно и ограничено, что пришло в задачу и что ушло из неё; каждое действие - строка в журнале задачи |
| Пакеты - только точная версия из PyPI и npm после OSV | Задача не ставит то, что не проверено |
| Импорт и выгрузка выключены, пока человек не задал папки в env | Без настройки песочница не видит файлов ПК и ничего на него не пишет |

| Запрещает или ограничивает | Чем платим |
|---|---|
| Выполнять сгенерированный код в процессе gateway или воркера | 0,7 с на старт контейнера на каждый запуск |
| Сеть в песочнице без запроса и мимо файрвола | Секунда на постановку правил перед запуском с сетью |
| Монтировать что-то кроме папки задачи | Код песочницы не правит репозитории - это работа агентов кода |
| Ставить пакеты без точной версии, из своих индексов, git и URL; пакеты Debian | Модель называет версию сама; недоступный OSV - установки нет |
| Перезаписывать файлы ПК при выгрузке | Занятое имя - отказ, модель берёт другое |
| Два запуска одной задачи одновременно | Второй ждёт до `SAM_SANDBOX_JOB_WAIT_S` |
