# ADR-006: Один цикл агента для всех ролей; вызовы tools - нативно и разбором текста через слой адаптера

**Статус:** принято


## Контекст

Модели SAM по-разному вызывают tools. Gemini и Anthropic отдают нативные `tool_calls`. Локальные модели в
LM Studio пишут вызов текстом, каждая по-своему: Harmony у gpt-oss, `<tool_call>` у Qwen,
`[tool_call: ...]`, голые Python-вызовы (3b7888d), GLM-4 и Gemma 4 (a74e8c6). Qwen через litellm пишет вызов
текстом даже там, где ждали нативный (ccf73fa). У Gemini свои требования к JSON Schema, из-за них падали
запросы 400 (c1b7449). Главный агент и воркер различаются только набором tools и промптом.

## Решение

- Один async-цикл `run_agent_loop` (`gateway/agent_loop.py`) для главного агента, воркера и агента Cortex; роли
  различаются набором tools, промптом и зависимостями (`AgentLoopDeps`), не кодом цикла (1f15d28, SAM-40).
- Вызов LLM идёт через слой адаптера `gateway/llm_client.py`, переключаемый настройкой: нативные tools по умолчанию,
  разбор вызовов из текста - на любом адаптере (3dfca17, SAM-25, ccf73fa).
- Схемы tools и сообщения приводятся под поставщика в одном месте (`gateway/provider_transform.py`, c1b7449, SAM-27).
- Защита от петель, дедуп повторных вызовов и запрет невыданных инструментов - в цикле, общие для всех ролей.
- Tool регистрируется классом, именем в списке роли и функцией (`gateway/agent.py`).

Адаптеры, форматы разбора, пороги защиты цикла и регистрация - `docs/features/agent-loop.md`.

## Рассмотренные варианты

**Только litellm.** Отклонён в SAM-25: litellm не справляется с вызовами tools у части локальных моделей;
оба адаптера оставлены с переключателем (`LLM_ADAPTER`, `POST /sam/llm/switch`).

**Разбор текста только в адаптере custom.** Был до ccf73fa, отклонён: Qwen через litellm писал вызов
текстом, задачи не создавались.

**Свой цикл на каждую роль.** До SAM-40 цикл жил в `agent.py`; при выделении (1f15d28) оставлен один
цикл. Отдельные циклы в истории не рассматривались.

## Риски и что с ними делаем

| Риск | Что происходит | Чем закрыт |
|---|---|---|
| Новая модель пишет вызов в новом формате | Вызов не разобран, текст уходит как ответ | Не закрыт: каждый формат - регулярка в `parse_channel_format`; SAM-57 переводит на нативный API |
| Разбор текста ловит вызов в обычном ответе | Лишний вызов tool | При нативном вызове `content` пустой (ccf73fa); для текстовых моделей не закрыт |
| Петля вида «опрос без прогресса» | Расход токенов | Тот же вызов с тем же результатом N раз заканчивает цикл ответом (`SAM_NO_PROGRESS_LIMIT`, SAM-69, SAM-80) |

## Последствия

| Обязывает | Что даёт |
|---|---|
| Новый tool - класс с `@register_tool`, имя в списке роли и функция в `TOOL_IMPL` | Набор tools роли виден в одном списке; цикл его не знает |
| Новый формат модели - парсер в `parse_channel_format` с тестом | Локальная модель вызывает tools без нативного API |
| Схема tool проходит `provider_transform` | Gemini не отвечает 400 на нашу схему |
| Любой агент SAM крутится в `run_agent_loop` | Защита от петель и дедуп действуют для всех ролей |

| Запрещает или ограничивает | Чем платим |
|---|---|
| Свой цикл модель-tool для отдельной роли | Особый случай роли настраивается через зависимости и флаги одного цикла |
| Вызов LLM в обход `llm_client` | Каждая новая возможность поставщика (поток, картинки) заводится в адаптере |
| Регулярки на каждый формат | Хрупкость: формат модели сменился - разбор молча сломался |
