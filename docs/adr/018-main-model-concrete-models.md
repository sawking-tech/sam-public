# ADR-018: Любой вход SAM идёт основной модели - выбору из конкретных моделей по приоритету

**Статус:** принято


## Контекст

До SAM-91 у SAM было два мозга. Голосовой ход шлюза отвечал и запускал воркеров моделью из `LLM_SOURCE` (GLM),
сессия Claude Code слушала тикер и поправляла постфактум, а чат монитора шёл в `sam_agent.run` и до сессии не
доходил. Источник `claude_code` в роутере - новый процесс `claude -p` на каждый вызов, без потока и без нативных
tools; замер 9 окт 23:34: «два плюс два» - 8,4 с (SAM-91). Первый звук через 8 с голосу не годится,
поэтому Claude Code нельзя поставить моделью роутера, как GLM.

Автор (SAM-91):
- 23:49: «Claude Code, GLM, Gemini - все основные модели, спектр с приоритетами»; механизм не привязан к модели.
- 00:11: «шлюзу всё равно, кто основная модель»; любой вход - голос, чат монитора, inject - уходит в основную
  модель одним вызовом.
- 00:13-00:14: у конкретной модели своя реализация; одна из них - no-op; для Claude Code - доставка хода во
  входящий файл сессии.
- 00:17: две абстракции - основная модель (выбор) и конкретная модель (реализация скрыта внутри).
- 00:19: инертность - текущая модель остаётся, пока доступна.
- 00:27: живость Claude Code - от самой сессии, не от тикера.

10 окт 00:54 (журнал): «Ты - часть огромной системы домашней и надо ассоциировать себя с ней, когда ты -
основная модель».

## Решение

Шлюз отдаёт любой вход основной модели и не знает, кто за ней. Основная модель - список конкретных моделей по
приоритету из конфига (`SAM_MAIN_MODELS`, по умолчанию `llm`); выбор на каждый ход: текущая
остаётся, пока доступна, иначе первая доступная. Конкретная модель объявляет имя, проверку доступности, рождается
ли ответ в шлюзе и как доставить ей вход не из голоса; реализации - `llm`, `claude-code`, `noop`. Механика -
`docs/architecture/gateway/main-model.md`.

Ведущий вне шлюза (`claude-code`) - обход для стендов без API ключа, где подписка на CLI работает вместо API:
терминал с запущенным `claude` выступает прокси, шлюз говорит с ним файлами шины; тем же путём идёт любой другой
такой CLI. Целевой путь - `llm` за роутером, где ход может вести Cortex за ACP (ADR-022); поэтому по умолчанию
первым стоит `llm`. Ведущий вне шлюза говорит с человеком от имени SAM, но историю и обещания держит шлюз:
переписка самой сессии после `/clear` не в счёт.

Сделано: ядро и голосовой ход (21de0d0), чат монитора и inject через основную модель (d8442ae), живость от
сессии (4fae952), старт сессии из `start_sam.ps1` (bcc6c06), подключение сессии к ходу (82a4764), агенты SAM от основной
модели вне шлюза (f98ec51), смена основной модели и поставщика модели шлюза без рестарта - `POST /sam/main-model`,
инструмент `switch_main_model`, недоступное не ставится (0d898e7, dba2a50, SAM-129, SAM-176). Не сделано (SAM-91): приоритет реального времени по статистике, составная проверка
доступности, канал WebSocket вместо `lead.alive`.

## Рассмотренные варианты

**Безголовый Claude по API подписки (`claude -p --output-format stream-json --resume`).** Не выбран на сейчас:
задержка холодного старта и повторное использование сессии не замерены. Теряем: шлюз как единственный путь хода -
у живой сессии ответ идёт мимо вызова LLM шлюза. Вариант остаётся конкретной моделью, которую можно добавить.

**Один `LLM_SOURCE` без запасных.** Отклонён: пропала сессия Claude Code - SAM молчит до человека (автор 23:31:
переключение без участия автора). Теряем: ничего, кроме простоты.

**Сессия Claude Code как наблюдатель сбоку (до SAM-91).** Отклонён: два мозга, чат монитора до сессии не
доходит. Теряем: быстрый ответ GLM первым, пока ведёт сессия.

## Риски и что с ними делаем

| Риск | Что происходит | Чем закрыт |
|---|---|---|
| Отметка `lead.alive` свежая, а сессия не отвечает | Ход уходит в никуда | Не закрыт; составная проверка с таймаутом хода - SAM-91 |
| Сессия закрыта | Вход без ответа | Хук SessionEnd удаляет отметку, через 5 с ход идёт `llm` |
| Модель часто ошибается, но доступна | Плохие ответы без смены | Не закрыт; приоритет по статистике - SAM-91 |
| Сессия не знает своей среды | Отвечает как терминальный агент | Роль в `lead_brief.py` и справка `docs/features/` |

## Последствия

| Обязывает | Что даёт |
|---|---|
| Любой вход шлюза - голос, чат, inject - идёт через основную модель | Новая модель подключается реализацией, без правки путей входа |
| Конкретная модель сама объявляет доступность и доставку | Смена модели между ходами без перезапуска |
| Ответ модели вне шлюза возвращается в историю шлюза (`/sam/session/{id}/reply`) | Монитор и история видят ответ любой модели |

| Запрещает или ограничивает | Чем платим |
|---|---|
| Шлюзу ветвиться по имени модели вне `main_model.py` и корня композиции | Особенность модели приходится выражать полем контракта |
| Сессии Claude Code в роли основной модели отделять себя от SAM | Сессия отвечает за обещания, данные до её старта |
| Менять модель без причины | Модель хуже по качеству, но доступная, остаётся до SAM-91 |
