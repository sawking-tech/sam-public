# ADR-012: Голосовой слой говорит с ведущим через файловую шину; gateway подключается мостом по WebSocket, Claude Code - через Monitor

**Статус:** принято


## Контекст

Сейчас клиент шлёт фразу запросом `/v1/chat/completions` и получает ответ целиком; итоги воркеров приходят
отдельно через `WSReplyListener` (`voice/voice_client.py:891`, d3b8ba7). Дельты модели уже есть
(`on_delta`, `gateway/llm_client.py:176,315`), но уходят только в монитор (`gateway/agent_loop.py:146-155`).
Голосовой слой (`voice/layer/bus.py`) говорит с ведущим через файлы JSONL: `voice-in.jsonl` - фразы,
`say-out.jsonl` - что сказать, `said.jsonl` - судьба реплик; ведущий - сессия Claude Code, которая слушает
тикер через Monitor. Автор 8 окт: Claude Code - альтернативный поставщик ИИ для SAM по этой схеме
(`docs/v1-goals.md`). Голосовой слой стоит у ПК, а gateway по плану - на сервере (CLAUDE.md, «Железо»),
поэтому файлы до gateway не дотянутся.

## Решение

Голосовой слой (ADR-011) знает только файловую шину. Ведущий подключается к ней одним из двух
способов; кто ведёт, выбирает основная модель (ADR-018) на каждый ход, без перезапуска:

| Ведущий | Как читает фразы | Как отвечает | Задача |
|---|---|---|---|
| gateway | мост на ПК читает `voice-in.jsonl` и шлёт фразу в `/voice/turn` (ADR-010) | дельты по WebSocket, мост собирает предложения и пишет каждое строкой в `say-out.jsonl` | SAM-09, SAM-53 |
| Claude Code | тикер (`voice/layer/ticker.py`) через Monitor | `say.py` | SAM-59 |

Мост читает `said.jsonl` и отдаёт gateway судьбу каждого предложения (ADR-013). Отмена хода - сообщение
по тому же WebSocket. Формат файлов - один модуль (`voice/layer/bus.py`).

## Рассмотренные варианты

**Голосовой процесс сам держит WebSocket к gateway, без файлов.** Отклонён: Claude Code как ведущий
потребовал бы второго протокола, а инструменты ведущего на шине (тикер, `say.py`) пришлось бы
переписать. Теряем: один переход и задержку опроса файлов (тикер опрашивает раз в 0,5 с,
`voice/layer/ticker.py:26`; мост - не замерено).

**SSE вместо WebSocket между мостом и gateway.** Отклонён: нет обратного канала для отмены и судьбы реплик.
Теряем: простоту SSE поверх HTTP.

**Claude Code через `claude -p` на каждый ход (сейчас поставщик `claude_code`, `gateway/llm_router.py:51-81`).**
Отклонён как ведущий разговора: новый процесс и потерянный контекст на каждой реплике, до 120 с. Остаётся
для служебных вызовов.

## Риски и что с ними делаем

| Риск | Что происходит | Чем закрыт |
|---|---|---|
| Мост упал | Фразы не доходят до gateway | Мост во вкладке с автоподъёмом (`scripts/sam_process.ps1`) |
| Связь с gateway оборвалась посреди ответа | Недоговорённое предложение | Судьба «неизвестна» (ADR-013); переподключение моста |
| Сессия Claude Code упала | Ведущего нет | Быстрая модель продолжает отвечать (ADR-014); подъёма нет, не закрыт |
| Форматы шины разъехались между слоем и ведущим | Тикер или мост читает не то | Один модуль формата с тестом |

## Последствия

| Обязывает | Что даёт |
|---|---|
| Голосовой слой пишет и читает только файлы шины | Ведущий меняется без правки звука |
| Gateway отвечает голосу потоком через `/voice/turn`, мост пишет по предложению в строку | Первое предложение звучит до конца генерации |
| Судьба каждого предложения возвращается ведущему | История содержит только прозвучавшее (ADR-013) |
| Итоги воркеров и свои реплики SAM идут в шину тем же путём | Один порядок и одни правила паузы для всех реплик |

| Запрещает или ограничивает | Чем платим |
|---|---|
| Голосовой слой не ходит в gateway напрямую | Лишний процесс-мост и переход через файл |
| Один ведущий на сессию за раз | Переключение gateway <-> Claude Code - сменой основной модели (ADR-018): по доступности или `POST /sam/main-model`, без рестарта |
| Запрос `/v1/chat/completions` для голоса | Старый клиент работает только до замены |
